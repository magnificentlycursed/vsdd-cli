# Phase 2a Primer: Test Suite Generation (Red Gate)

## Composition

You are entering Phase 2a (Test Suite Generation / Red Gate). Per the phase-domain composition matrix, load:

- **Quality Engineer** — primary; owns Red Gate authoring + falsifiability check

Plus the core always-on quartet. Skill mode.

## Dispatch & conformance discipline

Phase 2a's agent-work — authoring **and** implementation — runs as a **dispatched, conformance-audited agent**, never in the orchestrator session (the phases-dispatched keystone; supersedes the 2026-07-20 attended/autonomous split: human-judgment work is attended, all phase agent-work is dispatched). The composed governing context — this primer, the composed domains, and the supplements in scope — is delivered by **injection** at dispatch and **audited as skill invocations** (the skill-invocation audit: invocation is the activation signal; a recorded Read is the weaker signal; a paraphrase in the prompt is nonconformance). For a build-phase dispatch the composition SHOULD is this phase's matrix entry — the phase primer, its composed domains, the **core always-on quartet** (SO + SA + SE + QE; PE + PerfE when the project ships code), and the axis-activated product domains — which the conformance verifier audits as `WAS ⊇ SHOULD`. The full **process-governing set** (the eleven process-governing domains) is the audited SHOULD for **review compositions** (Phase 3), not for every build dispatch: wiring the whole set into a per-build gate would force every build dispatch to load all of it, against the efficiency thesis and cold-review independence.

## Phase-specific discipline

Phase 2a authors **failing tests** against the milestone's acceptance criteria from Phase 1c. The Red Gate is the committed test suite that **fails by default** when run against the current (unimplemented or partially-implemented) codebase. The Red Gate is what Phase 2b implementation must turn green.

The Exacting Mentor stance applies: "test that passes against an empty function body" is the failure mode — every Phase 2a test must assert the milestone's named behavior, not just liveness. The QE Dim 2 (test falsifiability) discipline: every test answers "what would have to be true of the implementation for this test to fail?" — if the answer is "the function panics" the test is testing liveness, not behavior.

Per-test discipline:
- **Failing-by-default at commit time** — `cargo test` (or equivalent) fails on every test added in this phase
- **Named acceptance criterion** — every test maps to one or more behaviors from DESIGN.md § Behavioral contracts
- **Specific assertion** — the test asserts the milestone's named behavior, not just "doesn't crash"
- **Edge case coverage** — empty / null / max-size / unicode / concurrent / partial-failure cases enumerated per behavior
- **Auto-scaffolded skeleton** — the `post-design-md-modification.py` hook auto-scaffolded the test file structure during Phase 1c; this phase fills in test bodies

The draft PR for the milestone opens at the first Phase 2a commit (per the per-milestone PR discipline). The PR template's manual-tests checklist is auto-generated by the PR-body generator for the layer (re-home-pending #842, off the retired `observe` namespace) from `manual-tests/layer-N.md`.

## Phase-completion criteria

Phase 2a closes when:

- All acceptance criteria from Phase 1c have at least one failing test asserting the behavior
- `cargo test` (or equivalent) returns non-zero (Red Gate is red)
- Draft PR is open for the milestone (`check-draft-pr-presence.py` hook validates)
- Manual-test checklist for behaviors that can't automate is committed at `manual-tests/layer-N.md`

Record the phase transition (`PhaseExited{phase: phase-2a, exit_status: complete, layer: <N>}`) in the crosslink session breadcrumb and the harness run record at the closing commit. The Red Gate opens Phase 2b.
