# Feature: Agent-first VSDD toolkit on crosslink

Tracking issue: vsdd-cli#597 (the respec) · Phase: build (Slices 2–7 open; see Decomposition) · Revision history at the end of this document.

## Summary

The toolkit enables and enforces VSDD for projects whose work is executed by AI agents under a human operator's direction. The product is an installed environment: context, constraints, and hooks wired into crosslink's seams, in which following the methodology is the easiest available path and deviation produces immediate, compiler-shaped feedback. The operator's session-start intent expands deterministically because the process is deterministic: the same project state and process spec produce the same next action from any competent cold agent.

Division of labor:
- **crosslink**: issues, dispatch (kickoff and swarm), worktrees, gates, sessions, knowledge, and raw usage capture. Tracking and orchestration live here so that they stay agnostic to the agentic coding tool.
- **vsdd** (methodology layer): process spec, phase state, composition, domain prompts, generated agent context, hooks, and the cost layer — the build-time token budget and the cost-and-efficiency report, a reader over the runtime harness's traces. Installed into crosslink's seams (rules, skills, hook config, house style).
- **mdatron** (conformance engine): validates every methodology markdown artifact, invoked at action time by hooks and at boundary time by gates. Methodology-agnostic.
- **the runtime harness** (Claude Code today; other agent runtimes later): executes the agents and provides the traces, hooks, and tool restrictions the controls ride on. Its surfaces are catalogued in the `claude-code-cli` supplement, never in this contract.
- **operator**: doctrine, scope, priorities, approval, and oracle authorship (acceptance criteria and manual tests). All other decisions belong to the process or the tooling.

## Project configuration

The project is described by configuration, not by a vocabulary of its own: the review configuration (`.vsdd/config.yaml`, preset-seeded and operator-customized — see Deterministic composition) and the project's declared characteristics in DESIGN.md, which the domain prompts' `activation_criteria` read to switch review domains on (a user interface activates accessibility and UX; user data activates privacy; network exposure activates red team and security; an AI runtime activates the AI engineer). Configuration options are attributes of the project, never headline concepts of this contract.

This project's configuration:
- **Review config:** the `thorough` preset — the toolkit governs other projects, so its defects propagate. The full default domain set plus the mutation floor.
- **Phase 5 strategy:** mutation testing with a kill-ratio floor enforced in CI on `vsdd-core`; fuzz testing on this toolkit's own input parsers (config, state, registry, the exception register, runtime-harness settings, tracker payloads, the install manifest, and the statusline repo-set config; each repo's design owns its own fuzz surface); property-based testing on the pure core per the Verification architecture; no proof execution, since no cryptographic or safety-critical surface exists.
- **Phase 6 strategy:** applicable at the v1.0 cut — before publishing, confirm that specification, tests, implementation, and verification each stand complete and consistent with one another.

## Behavioral contracts

Contracts are referenced by their exact heading names. Each states its normative content, then its falsification path, then the recorded evidence that motivated it (by handle; the record carries the narrative — see References and name map for the handle grammar).

### Deterministic phase answer

"What phase are we in?" has exactly one correct answer, derivable by any cold agent at any time.

- The phase state is a written artifact in the project repo, `.vsdd/state.yaml`: current layer, current phase, open-findings pointer, last gate result, active composition, and the published marker once the first-publish act writes it.
- The state advances only at phase boundaries, by the agent, in the same commit as the boundary evidence. Its validation is vsdd's own — shape at read and write, and consistency-against-evidence checks (a state claiming phase 2b requires a recorded red-gate result for the layer) — because the state file is not markdown and so not mdatron's.
- The state rides crosslink's session machinery: the phase pointer travels in session breadcrumbs and is re-injected on resume after compaction; `session start` surfaces phase status with the prior handoff; phase boundaries require handoff notes; each phase execution and each slice is a crosslink milestone, so tracker-side progress and the state corroborate each other.
- When the tracker is unreachable, the phase answer is computed from the state artifact alone and reported as degraded. The artifact is authoritative for the phase answer; a present-but-disagreeing tracker files an integrity finding without degrading the answer; the answer is degraded exactly when corroboration is absent or unusable.

Falsification: two cold sessions given the same repo and tracker state answer differently (a spec defect, chargeable to the spec rather than the agents); a state artifact inconsistent with repo evidence surviving its consistency check.

Evidence: session entry depended on prose reconstruction since the suite era; in the June 2026 cycles the flow's position was lost entirely (vsdd-cli#12, vsdd-cli#13; the operator interview, knowledge page `operator-interview-2026-07-18`).

### Directive reconciliation

Every mid-flow operator directive is classified before execution — change classification, applied to the methodology. The classifications: phase-4 routing (file the routing, name the target phase); spec amendment (amend the contract, then act); documented exception (execute, record via `crosslink intervene`, state where the flow stands and the re-entry path); or new work item (a feature entering at phase 1a, or a defect fix entering the fix lane of Finding lifecycle in one place — the classification also states which acts are attended and which are dispatched, per Recorded review dispatch).

- The classification is stated to the operator at the moment of receipt, including the inferred scope: whether the operator's words are read as a specific instruction or as instances of a general rule.
- Silent execution of an unclassified directive is a named defect. The operator holds the authority to redirect; the agent holds the duty to say what the redirect does to the flow.
- When a crosslink or harness mechanism serves the directive (milestone, session, hook, skill, config), it is named and offered at classification time (the AI Engineer domain's duty). The second occurrence of an operator correction or struggle obliges a proposed mechanization.
- The duty is symmetric: session-originated code-touching work carries the same classification duty; its statement-target is the finding issue, recorded at filing before implementation, with the scope reading (in or out of the governed set, with the reason).

Falsification: a directive executed with no classification recorded in the tracker or session record; a recorded classification lacking the scope reading or, for a new work item, its attended/dispatched split; a directive served by an available crosslink mechanism with no mechanism named at classification; a second-occurrence correction with no proposed mechanization; a session-originated change to the governed set implemented with no recorded classification.

Evidence: in the June cycles the operator issued directives believing them to be phase-4 routing; they were executed unclassified, the flow was orphaned, and 137 findings accumulated with 82 orphaned before the operator noticed (vsdd-cli#12, vsdd-cli#13). Scope drift has failed in both directions: single utterances became named schema concepts, and illustrative examples were wired as enumerated special cases (knowledge page `operator-interview-2026-07-18`).

### Phase exit by gate

A phase closes only when its exit gate passes. Gates are commands; `crosslink swarm gate` runs them, and their results are recorded in the state artifact and the tracker.

- Red-green, mechanized: phase 2a closes only when the layer's test suite fails against the pre-implementation commit and the failing run is recorded; phase 2b closes only when the same suite passes at HEAD. The gate performs the checkout and run; agent assertion plays no part.
- Phase 3 closes only at the stop signal — a round whose findings are all false positives — with all round findings filed. Phase 4 closes only when the unrouted-findings query returns empty.
- Mutation floor: when the review config declares one (the `thorough` preset does), the mutation kill-ratio on changed code is a standing gate criterion.
- The red gate applies at fix scale, mechanized like the layer gate. The finding issue records the baseline commit (for a single-commit fix, the fix commit's parent), names the defect's characterization test(s), and declares the expected failure kinds as a set drawn from the versioned failure-kind enumeration. The gate checks out the baseline, applies the named test(s) to it, runs them in isolation, and requires red there and green at HEAD; the green half also runs the standing suite at baseline and HEAD and compares by runner-reported test path, so that no test which passed at baseline fails at HEAD, and no test which passed at baseline vanishes undeclared.
- An executed test, never a skipped one: a valid red is a run-time failure of a test that built, was collected, ran, and failed; a valid green is the symmetric executed pass. A test that is skipped, ignored, filtered, or not collected is neither red nor green — its own recorded state, satisfying neither half. A test that fails to build or be collected against the baseline is not a demonstration.
- The three no-executed-test forms each require validator approval, on one bar, so relabeling between them buys nothing: a declared compile-defect (the defect is that the code under test fails to compile — its compile-red then validly satisfies); a surface-limitation (the defect's test cannot be expressed against the baseline surface); and a broken verification surface (a suite that cannot run — the recorded failing state is the red evidence, and the gate's own baseline run attempt rejects the claim when the suite in fact runs).
- Removal-shaped changes are declared, never silent: a test that passed at baseline and is deleted, relocated, or left dormant at HEAD takes its declared, validator-approved lane (deletion, mapping, or disablement) or fails the delta; the join fails closed rather than dropping a vanished test. The mechanics that close specific evasions of this rule — set-valued mappings, decoy targets, bulk set-equality, targets vanished from collection, dormancy inherited by relocated tests, split gate invocations — are held in the regression corpus (References) and built when Slice 4 needs them or when an evasion occurs.
- Wrong-reason is a mechanical comparison: recorded test identity against the finding's declaration, and recorded failure kind by membership in the declared set — never a prose judgment. The flake-resistance policy covers the named tests and the suite delta alike; a test that passed at baseline and aggregates flaky at HEAD fails the delta.
- A fix that landed ungated is remediated by the retrofit form: the same gate run performed after the fact against the recorded baseline, marked retrofit on the finding issue — a full record where the test is expressible, the validator-approved surface-limitation where it is not, partial evidence declared as partial. The retrofit closes verification debt, not the process breach: the exception record stands.
- Tests authored alongside the fix and never shown failing first are the assertion-based transition this gate exists to block, at any scale.

Falsification: any phase transition in the state artifact without its recorded gate evidence; a commit in the governed set owned by a finding issue with neither a recorded gate-performed red-and-green run against its recorded baseline, nor a validator-approved no-executed-test record, nor a valid waiver marker (valid only after first publish — a pre-publish waiver marker is itself flagged).

Evidence: the layer-7 red gate of `issue-tracker-cli` passed against the pre-implementation base with zero genuinely failing tests, and its last plan issue carried three closure comments while remaining open — both assertion-based transitions a gate would have blocked. At fix scale, the mdatron path-confinement hotfix landed direct-to-main with its test suite authored alongside the fix and never demonstrated failing first (mdatron#51).

### Finding lifecycle in one place

Finding lifecycle state — classification, routing, closure — lives in crosslink issues only. Review narrative may exist but carries no state.

- Findings are filed in the subject project's tracker; the subject project field is a routing instruction the tooling enforces.
- Filing is evidence-gated: a finding carries checkable evidence at filing time — a file-and-line citation that mdatron verifies against the working tree as it stands (uncommitted edits count), or a failing test where the surface allows one. A finding citing absent content is rejected at filing.
- Every finding names an owner domain and a validator domain that differs from the owner; sanity-check is the validator of last resort. The halves of an adversarial pair — an author-side domain and its cold-reader domain — never share a reviewer session.
- Lifecycle acts use crosslink's typed comments as the single vocabulary: closures are `result` comments carrying the evidence reference, operator decisions are `decision`, routing is `plan`.
- Closure is evidence-graded for fixed findings: a fixing closure references a commit, gate run, or test; otherwise it is invalid. Disposition closures — won't-fix, false positive, and consolidated into a named survivor — close immediately with their disposition recorded; git and tracker history are the audit trail, so closed records need no open placeholder. (The review-entry schema's enum tokens for these dispositions — `dismissed`, `hallucinated`, `consolidated` — predate this alignment and rename with their schema pair, Slice 5.)
- Waivers are enumerable: any waived criterion, deferred obligation, or accepted risk carries a single canonical marker that one search lists completely.
- Tracker objects are cited by lookup handle wherever they are referenced (the handle grammar in References and name map); a reference that cannot be resolved by a crosslink query or a path is a defect the conformance checks flag.
- Defect fixes are new work items. The governed set is decidable by enumeration alone: executable source including test source, build and dependency manifests, emitted diagnostics, schemas, and generated-artifact sources. Mechanical passes (formatting, comment-only edits that alter no executed doc-test, renames) are outside the lane only when the commit states the exclusion and carries its unchanged-verification check. A defect in code the current slice is building is slice work under the slice's own red gate; the fix lane governs defects outside the current slice's declared build scope. In both cases filing precedes implementation.
- One owning finding per fix commit. Symptoms sharing one root cause consolidate before the fix: absorbed findings close with the consolidated disposition and the survivor's handle; the survivor lists every symptom, names every test, and carries the union of the absorbed findings' labels — consolidation never narrows the composition.
- The fix inherits the process at fix scale: the red gate; a composition computed by the same function under the same integrity rules, with the finding's labels in place of the project configuration (software engineer with its cold-reader validator at minimum; a security label adds the security domain); the mutation floor when the config declares one; the implementation language's supplement; and its reviews as recorded dispatches. Inline review by the implementing session is a named violation, whatever record it narrates.
- There is no bypass lane before first publish, and the falsifiers enforce it: the waiver escape activates at first publish (the promotion act writes the published marker into the state artifact), and before that marker exists a waiver marker in the governed set is itself a flagged condition. After first publish, a bypass is a waiver under the canonical marker — loud, annotated, and enumerable.

Falsification: lifecycle state found in a review-log file that differs from the tracker; a fixed-closed finding without an evidence reference, a disposition closure without its recorded disposition, a consolidated closure whose survivor reference resolves to no finding, or a survivor carrying fewer labels than the union of its absorbed findings'; an open finding without an owner; a filed finding whose citation fails working-tree verification; a governed-set commit whose structured evidence section names no owning tracker issue and no valid waiver marker; a fix commit whose evidence section names one finding while its gate record shows tests for another.

Evidence: classification state lived in both review-log files and tracker issues during the June cycles with no synchronization, and drifted; 7 of 8 findings in one `bookmark-cli-manual` review round cited code absent from HEAD; 137 findings sat unrouted until the operator intervened (vsdd-cli#12, vsdd-cli#13). For the fix lane: a security-labeled path-confinement defect was fixed direct-to-main in mdatron through none of the increment gates — competent work through an ungated lane, which is what made it quiet (mdatron#51); the retro-reviews of that fix ran inline in the orchestrating session under hand-coined review-log names (mdatron#52).

### Deterministic composition

Given the phase, the project configuration, and the review config, the active domains and their dispatch shape are computed. At fix scale the finding issue's labels stand in the project configuration's position — one function, one integrity-rule set, both scales. The function's second input is the composition scope, whose domain ships as versioned data: the phase enumeration plus the fix-lane scope value — the fix lane is not a phase and is never called one.

- The domain roster partitions totally into three classes. The **core always-on quartet** — Solution Owner, Solution Architect, Software Engineer, Quality Engineer — composes on every dispatch of every phase. The **process-governing set** — the quartet together with AI Engineer, Platform Engineer, Red Team, Security, Data Engineer, Documentation Reviewer, and Technical Writer, with Performance Engineer joining whenever the adopter ships code — is inherited by every adopter for the harness to function at all: the process dispatches AI, enforces through CI and hooks, is circumventable and oracle-trust-dependent, runs on schema data, and produces governed prose. The **product-reviewing** domains — UX, Accessibility, Privacy, Localization, and the product activation of Red Team, Documentation Reviewer, and AI Engineer — activate per the project configuration. The meta-domains, Sanity Check and VSDD Methodology, compose at phase level as validators, never as roster members.
- Audit level: the process-governing set (plus the configuration-activated product domains) is the expected set for **review compositions** — the multi-lens cold-review rounds of Recorded review dispatch — and the conformance verifier blocks a review whose observed set is not a superset of it. A **build-phase dispatch** carries only its phase primer plus the action- and configuration-activated supplements the task summons — never the whole review roster, which would defeat both the efficiency thesis and the cold-review independence the roster exists to provide.
- The review config is a file, `.vsdd/config.yaml`, with layered loading modeled on crosslink's config: shipped presets, then project config, then local overrides. Presets are suggested starting points, each with an associated cost band. Fields: active domains, round budget, stop sensitivity, model tiers and effort levels (settable per lens and per model-running stage of the review loop — its cold rounds, its fix passes, and its terminal verify round, which decides the stop signal and takes the higher default dial; mechanized gates run no model and take no dial), mutation floor, cost bands. A preset's cost band prices the static context bill only; effort's runtime spend is reported from the traces.
- Config integrity rules are validated by mdatron: pair co-activation (activating an author-side domain activates its cold-reader domain), pair separation at dispatch, and validator-differs-from-owner. The per-domain bar holds at any active-set size.
- A mid-cycle config change is an operator directive and receives change classification, recorded in the tracker and the trace.
- Identical inputs produce identical compositions. The rules above carry the doctrine; presets are starting points.
- Composition operates at two timescales. Session composition selects domains per phase. Action-time activation binds content to its moment mechanically: every supplement declares its activation trigger as a required field, and the harness surfaces whichever supplements match the task at hand, with a hook backstop when a file is edited before its matching supplement was read. Adding a supplement means content plus trigger, with no harness wiring.

Falsification: two sessions computing different compositions from identical inputs; an emitted context artifact differing from its source data; a config violating an integrity rule surviving validation; a review composition that omits a process-governing-set domain, or a review marked conformant while missing one; a build-phase dispatch audited against the review roster rather than its phase primer and activated supplements.

Evidence: the composition matrix lived as prose that agents applied from memory; the tier system was cut in practice while reviews ran at unrecorded ad-hoc compositions; the crosslink-usage knowledge sat in a review-time supplement while the operator believed crosslink was in use and no mechanism was positioned to notice (knowledge page `operator-interview-2026-07-18`).

### Recorded review dispatch

Phase 3 dispatch runs on crosslink swarm. Every dispatch produces a manifest: what was sent, to which reviewer role, containing which inputs by content hash, under which composition, at which model tier and effort level, what came back, and where findings were filed.

- Reviewer roles are tool-restricted; a critic role cannot edit. Operator approval — ratification, gates, waivers, the dispatch approval — never belongs to an agent; a validator's approval record is a different act, signed by its domain identity. A domain prompt is criteria content; a reviewer role is the tool-restricted agent identity that receives domain prompts at dispatch — pairing constraints bind domains while session constraints bind roles.
- Dispatch manifests and filed findings are signed with crosslink agent identities. Identities are approved before dispatch — approve-then-dispatch, or a pre-approved identity pool — so an agent's earliest tracker write never races its trust approval.
- All phase agent-work is dispatched; only human judgment is attended. Design authoring as much as implementation runs as a dispatched, conformance-audited agent, exactly like reviews, because the operator session is not a dispatched agent and its in-session phase-work is unaudited — the ultimate bypass. The operator's attended acts are the irreducible slots named in The operator authors the oracle plus orchestration. Execution runs on the container kickoff vehicle (`kickoff run --container`): the container is non-interactive by construction, so the runtime harness's consent dialogs cannot render and the run proceeds headless; that non-interactivity is the mechanism, never gate-disabling — permission-bypass flags are not adopted, the operator's dispatch act remains the approval, and the crosslink hooks are the policy layer inside the isolation. The attended local path is interactive and stalls headless; it is carried under the exception register until the container image is confirmed usable. The mode is never chosen at dispatch: it derives from which side of the split the work is on. A detached execution dispatch on an attended-shaped vehicle — a local session with nobody attached — is a named defect, not a lawful middle. Bootstrap interim, marked: until the dispatcher, the injection seam, and a working kickoff land, phase agent-work done in-session is hand-audited (compositions hand-loaded, invocations noted) and recorded as such at each act, never as the target.
- Independent review: review by a different agent, never given the author's reasoning, with no shared conversation state or memory. A reviewer may be warm on the raw artifact (the raw diff, design, or contract slice) but never on a curated summary, which re-imports the author's blind spot; true cold — re-load the raw yourself — is reserved for the terminal rounds that guard collective anchoring.
- Dispatch preflight: before any dispatch, the preflight checks pass. The check is three-valued — pass, fail, unknown — and fail-closed: a check that cannot determine its answer blocks like a failure. The members ship as versioned data (container runtime with its daemon, consent state, identity approval with key material provisioned, model credentials in the launch environment, and project-server trust and load state), each carrying its observation binding; a failed or unknown member blocks dispatch naming the member. Environment provisioning is a precondition performed once by the operator. The dispatch record names the operator act that invoked it — invocation provenance is recorded, not assumed. The vehicle's working tree carries the payload half by construction, and the preflight's resolution checks run against the vehicle's tree, so a vehicle born hollow fails preflight rather than launching silent. During bootstrap the preflight is a compensating control: a dispatch records its checks as a hand-performed checklist until the preflight command ships.
- A dispatched agent that never started is a launch failure — a distinct, loud state, never a clean round — detected by crosslink's instruments: the launch-status record written before the launch act, session records, and heartbeat staleness (which also makes started-then-stalled loud). The state has two signatures: the record present with no session activity following, and the record absent (the launcher died before its pre-launch write). A first write landing after a dispatch's dead classification joins as a flagged late-writer under the closed dispatch, never a silent revival. Counting tracker filings is not the instrument: a clean review files nothing.
- Unresolved design questions reaching a dispatched run produce a blocker record on the owning issue and work proceeds on the unblocked parts — escalate, never guess, never stall silently.
- Build dispatches carry scope manifests: a pre-declared writable file set per task. An off-manifest write blocks with a manifest-expansion request. One concern per manifest keeps commits revertible.
- Coverage is declared: the manifest records which domains did not run and why (no matching configuration, declined by config, or deferred with a trigger). Absence of findings and absence of looking are distinguishable facts, and neither produces tracker issues.
- Round stop rules follow the whitepaper: continue on any real finding; stop when a round is entirely false positives; rounds past the stop signal require named new evidence. A finding is a false positive when it does not resurface across rounds — never adjudicated by a per-finding verifier fan-out.
- The review budget follows the evidence: cold review concentrates on code-shaped artifacts; prose artifacts get the operator's read and external cold readers; spec-stage structural review — small, early, few lenses — is a first-class use of cold review.

Falsification: a Phase 3 record without a manifest; findings whose provenance traces to no dispatch; a build commit touching files outside its declared manifest; a domain that neither ran nor recorded a reason; an unsigned manifest or finding where signing is configured; a tracker write signed by an identity whose approval postdates the write; a manifest missing its recorded model tier or effort level; an execution dispatch on a detached vehicle; a dispatch with no preflight record, or whose unknown result was treated as a pass; a dispatched run reopening a recorded operator decision with no change-classification record; a run's artifact resolving an open design question with no blocker record; a dispatch whose record traces to no operator act; a phase artifact produced in-session with no marked hand-audit.

Evidence: 18 reviews of one repo were filed into a sibling repo's review-log; a bundled commit had no rollback path; 23 empty no-findings issues were filed to prove domains had looked; the respec's own tracker events ran unsigned under audit-mode enforcement (vsdd-cli#12, vsdd-cli#13). The mdatron kickoff pilot's three agents idled to timeout, indistinguishable from clean from the outside, and its earliest tracker write raced its trust approval (mdatron#52; knowledge page `attended-design-autonomous-execution`). The phases-dispatched rule's founding evidence is the vsdd-cli#840 cycle's own opening: the orchestrator dispatched a general-purpose agent with a paraphrase of the composition until the operator caught it (vsdd-cli#840).

### Conformance at action time

mdatron validates the methodology's markdown artifacts — DESIGN.md structure, the route table, domain prompts, generated context, the registry — with rustc-shaped diagnostics, invoked by hooks at action time and by gates at boundary time. Its scope is Schematron for Markdown with rust-like errors for agent-first workflows; the state artifact's validation is vsdd's own.

- Spec drift is checked mechanically: design docs pin a content hash over the files they govern, and a governed-file change without a re-pin fails the gate.
- Session entry is enforced: edits to governed files are blocked until the session has read the governing docs, configured per project.
- Vocabulary and register are governed. A register spec (concrete named anti-patterns, because agents anchor on the register they read) pairs with the vocabulary registry. Term additions carry earned-by-recurrence justification. mdatron checks the mechanical subset at action time: invented label schemes, unregistered abbreviations, new-coinage detection, and the listed register anti-patterns. Every term in this contract is either a standard term from a named reference lexicon used in its standard sense, or a project term registered once with a definition and its nearest standard neighbor; nicknames for rules are not terms.
- Vocabulary and schemas have a stability lifecycle. Unstable terms and schemas may be renamed or deleted freely and carry zero compatibility obligation. Promotion to stable is an explicit operator act, gated at first publish, never agent-initiated. An utterance is a concept only after registration: agents do not reify casual operator phrasing into named terms, frontmatter fields, error codes, or schema elements. Forward-only discipline applies to stable artifacts only.
- The artifact set is closed-world: the route table is an allowlist, and an unrouted artifact blocks. New artifact classes and new name slugs are registration acts under the same stability gate. Generated artifacts carry computed names derived from their manifest; agents never hand-name what the tooling can name. Branch names are the same class: one canonical branch grammar ships as registered data declaring both forms (the session-scoped form before hub sync, the display-ID form after), a process-integrity query in Status reports off-grammar names among this clone's own refs, and a pre-push hook warns toward the preferred form without rejecting a registered one.
- Enforcement logic lives in mdatron pattern and registry data. Hook scripts stay thin wrappers; a new defect class is closed by adding a pattern.
- The paved path is the default vehicle: every methodology act with a crosslink workflow rides it — design authoring the crosslink design workflow, spec-to-build the read-only gap analysis, autonomous execution the container kickoff, phase-3 rounds the swarm review (activating at the Pilot criterion's pass), gates the swarm gate, run monitoring the check surface. Going off the paved path while it exists carries a stated reason or is nonconformant; a one-off divergence is recorded as a change classification or a decision comment, and a divergence that stands — riding off-path across acts or persisting as a fallback — escalates to an exception-register entry. Where a ridden workflow's conduct conflicts with this contract's discipline, the contract governs. The paved-path map ships as versioned data owned by the AI Engineer domain and is the single home for every act-to-vehicle binding: crosslink workflows, skills, domain summonings, and session dispatch surfaces alike. Swarm entry is bound: `crosslink swarm init --doc .design/build-plan.md` is the entry gate, proposing the open-phase set from the build-plan projection.
- The exception register is the departure side of the map (`.vsdd/registry/deviation-registry.yaml`; adopters receive the empty template): each entry carries its stated reason, exactly one machine-decidable retest trigger, a review date computed from the 30-day default, and the Solution Owner decision reference that creation, re-arm, and resolution each require. `vsdd gate` enumerates standing entries and fails loud on a lapsed review date or a fired trigger without a newer decision reference — mechanical since Slice 1. That a standing deviation gets an entry at all is forced by the stated-reason discipline and the review lenses, convention grade; the unregistered deviation is the named residual no gate reaches.
- The installed environment is a closed world like the artifact set: an install manifest — versioned data — lists every artifact the environment expects (skills, hooks, servers the runtime-harness config references, rules files, and git hooks) with its source and its lifetime half, tracked wiring or per-clone payload. The installed-artifact-integrity check verifies every reference resolves — three-valued, fail-closed — and its result surfaces in Status; a wired-but-absent artifact is a loud finding, never a quiet no-op. Installed hook wiring is fail-closed, so a missing payload is a nonzero exit in the runtime harness rather than a guarded no-op. Additions, the operator's included, enter by the recorded pair — artifact plus manifest entry together.
- Sessions launch from the repo they govern: the runtime harness binds project config at the launch directory, so a session launched elsewhere binds none of the repo's enforcement. The workspace root serves cross-repo orchestration and the composed statusline only; the installed-artifact-integrity check's first member is the binding itself.
- Availability is not activation: a skill in the runtime harness's listing loads only by invocation or by the model matching its description — a judgment, not a mechanism. What an act requires in context arrives by one of two reliable paths: injected by hook at the act, or gated on its recorded Read, which converts "should have loaded" into "cannot proceed without loading". Phase entry, the primers, and supplement activation take these paths — never the description match, never operator reminders, never agent memory. The Read record's guarantee is entry-time, honestly bounded: content evicted by compaction is a named limit, and post-compaction re-entry re-reads. Whether loaded content was followed is audited by the commit evidence sections cross-checked against recorded Reads, the hook trace log against git history, the conformance families over outputs, and — for judgment-shaped guidance — the cold review receiving the same slice, the one instrument that catches read-but-ignored.
- Artifacts are retrieval-friendly: governed artifacts serve the human reader in full and the agent retriever in slices — unique exact-name section anchors, summary-first sections, stable handles, no intra-section forward dependencies — so a targeted question resolves with one search and one section read. The mechanical parts are conformance checks; commit messages carry structured evidence sections.

Falsification: a governed file changed with a stale pin passing the gate; a governed edit absent from the hook trace log; a file admitted with no route; an artifact whose name is underivable from its manifest or registered grammar; an off-grammar branch among this clone's own refs surviving the refs query; a coinage, nickname-as-term, or register violation in a governed artifact surviving the check; a methodology act off the paved path with no stated reason; an installed-artifact reference whose artifact is absent surviving the integrity check, or an installed artifact absent from the manifest; an act requiring governed context that proceeded with neither injection nor a recorded Read; a work session whose project root differs from the repo root it governs.

### Verifiable conformance and efficiency

The methodology harness proves, from the trace, that its own disciplines fired for every dispatched agent — the phase primer, composed domains, and supplements were loaded; the intended tools were used; the run was right-sized — and that every authored control is exercised. The design rationale is archived on the knowledge page `verifiable-conformance-and-efficiency`; this member is the contract.

- **Authored is not exercised** — the governing law, the sibling of Availability is not activation. The install manifest proves a mechanism is installed; this member proves it fired. Every control the methodology authors emits a provable "it ran" trace, audited against a **control-effectiveness registry** — the exercise-layer twin of the install manifest, in which a control lands paired with its fire-check — and fails loud on authored-but-never-exercised. Three properties make the law falsifiable rather than a liveness check: (1) each registry entry pairs the control with a committed negative-case fixture proving it fires on a known-bad input and stays clean on a known-good one — an entry with only an "it executed" trace is vacuous and fails the audit; (2) registry completeness is keyed to an independent census — the install manifest, or a build-break that fails when a control-defining construct emits no entry — never to self-registration; (3) each entry declares the occasion on which the control is expected to fire, and when the occasion is absent the honest status is no-data, never clean. This is the design-effectiveness versus operating-effectiveness distinction of internal-controls audit, applied to the methodology's own controls.
- **The oracle is the trace, synced and tamper-evident — and nothing else.** The conformance oracle is only the trace as synced to the crosslink server and made tamper-evident by corroboration. The local copy on the worktree disk is agent-writable, so it is not authoritative: the verifier rejects a local or un-synced trace and reports no-data, never clean. The sync channel is an upstream crosslink dependency, carried in the exception register until it lands; until then every conformance verdict resting on it is no-data. Evidence discipline: the observed set is the trace's tool-use and usage events only; the expected set is recomputed by the verifier from the composition function, never taken from any agent-authored declaration — a per-run composition declaration is a claim to verify, never the oracle. The checked agent is untrusted with respect to its own conformance; this trust-boundary placement is hard to undo and is defended from the start.
- **Expected and observed.** The composition function computes the expected context set (role-scoped: for a review composition, the process-governing set plus the configuration-activated product domains; for a build dispatch, the phase composition matrix's primer and composed domains; in both roles the runtime and project always-on supplements). The verifier reads the observed set from the synced trace, recomputes the expected set, and blocks when observed is not a superset of expected. The role is derived from the recorded phase, never from an agent-declared field, so a Phase-3 run cannot self-label build to earn the thinner expected set.
- **Phase is recorded.** Every dispatched agent's run carries the phase it executes, sourced from the state artifact and the crosslink session breadcrumb, not self-asserted.
- **Primer, domains, and supplements are present by injection; missing terminates.** The phase primer, the composed domains, and the supplements in scope are delivered by the golden-path dispatcher (`vsdd dispatch`) and injected at dispatch; a dispatch whose composed context lacks a required member fails preflight and is terminated before it runs, with a message routing back to the golden path. Supplement activation has three tiers — runtime-determined always-on (the runtime harness's supplement whenever the runtime is Claude Code; `bash` for every agent), project-determined always-on (`rust` for this project), and task-determined (per surface in scope). Preventive termination holds only at the interception points vsdd sits on — `vsdd dispatch`, crosslink's kickoff and swarm preflight, and the git and CI operations vsdd gates; a dispatch through the runtime harness's native spawn primitive bypasses them and is caught only by the post-hoc trace audit, detective not preventive, and its preventive equivalent is an outer-harness dependency, carried in the exception register.
- **Skill invocation is the activation signal.** The primer and the composed domains are delivered and audited as skill invocations — the record of which skills the agent invoked is the unambiguous activation signal, checked against the expected set; a recorded Read is the weaker signal (content loaded, may be skimmed); a paraphrase in the prompt is nonconformance. Supplements are delivered by injection, emit no invocation event, and are audited on injection presence — auditing a supplement as a missing invocation would be a check that can never pass. Two fail-loud checkpoints: preflight (not injected → terminated) and post-dispatch (a required primer or domain skill not invoked → fails loud even if the file was Read).
- **Intended tools, no hand-rolled paved path.** A methodology act uses its mapped tool; a shell string re-implementing a mapped tool with no stated reason is flagged. Every control names its correct mechanism — tool, hook, skill, crosslink workflow, CI leg, sentinel — and rides it; the correct mechanism must be the path of least resistance so that the correct path is the only path.
- **Model and effort are specified.** Every dispatch manifest records explicit model and effort dials; unspecified dials fail closed at preflight. The dials' authoritative source is the dispatch manifest, because a preflight check runs before the trace exists. Appropriateness of a specified value is an AI Engineer judgment surfaced as advisory, never a fail-closed gate.
- **Personas and supplements are controls, not prose.** Their enforceable content becomes conformance checks; their required content is delivered by injection; only irreducible judgment-shaped guidance remains as prose, injected and audited by the cold review that receives the same slice.
- **The process is itself checked and red-teamed.** A design or review cycle's own dispatches are subject to every control above, and Red Team reviews both the process (was the correct path the only path, or was a bypass available and taken) and the artifact.
- **The operator session is audited too.** It is not a dispatched agent, so its control is the session-start hook — injecting the session skill, the runtime always-on supplements, and the phase pointer — plus the read-gate on governed acts; session-start-hook-fired and session-skill-invoked are audited and fail loud, over the synced copy only.
- **Dispatch spend-shape bound: three legs, honestly graded.** (1) Declaration-completeness at ratification, block-grade: a composition that binds the lens set but omits its fan-out shape or agent-count ceiling fails the gate — enforceable because it reads a document, guaranteeing a ceiling exists and preventing nothing beyond that. (2) Runtime admission control, the only leg that prevents a spend: per-agent token or cost admission control exists on the target vehicle (crosslink's per-agent budget cap) and on the fallback path; an agent-count interceptor exists on neither and remains the unbuilt leg, carried in the exception register — preventive claims are made only for what exists. (3) Records-based detection, post-hoc and advisory: the cost-and-efficiency report flags a fan-out that breached its ceiling; it reads records after the spend and is never called fail-closed. Refutation of a finding is across-round non-resurfacing, specified at leg 1 so that a synchronous per-finding verifier fan-out cannot be substituted for it.
- **A regression corpus is the Red Team coverage bar.** The cycle maintains the enumerated escape paths agents have taken against the implemented system — this project's own cycles included — and Red Team coverage is audited against it: for each escape, the control, its non-forgeable corroborated trace, and whether the control shifts the incentive gradient or only detects. Detection-only is not governance: an advisory-only control in the bootstrap window is marked advisory, never called enforcement; a check whose input is unavailable reports no-data, never clean. A probe-found escape is added as it is found.
- **Secret redaction is a three-leg ladder.** Accidental leakage in committed text: the `check-anonymization` pre-commit hook over the shipped anonymization patterns (authored, not yet wired — a control-effectiveness-registry entry that fails loud until it is). Accidental leakage in the trace: sync-side redaction on the crosslink sync channel, applied before the corroboration copy is formed, so it neither runs agent-side nor breaks the corroboration hash (an upstream dependency, in the exception register). Deliberate exfiltration by an untrusted agent: least privilege — secrets scoped out of the agent's context and environment — the only credible defense against a deliberate actor; pattern redaction is never claimed as one.
- **The cost-and-efficiency report** — see Cost is knowable.

Falsification: a control absent from the census-keyed registry, present with only an it-ran trace, or reported clean when its occasion was absent; a conformance verdict over a local or un-synced trace marked clean; an expected set taken from an agent-declared composition; a review self-labeled build to earn the thinner set; a required primer or domain skill uninvoked yet the run marked conformant; a supplement audited as a missing invocation; a phase artifact with no conformance-audited dispatch record and no marked bootstrap hand-audit; a ratified composition that binds lenses but omits shape or ceiling; a records-based flag or an unbuilt interceptor labeled fail-closed; a refutation implemented as a per-finding verifier fan-out; a regression-corpus entry missing its control, trace, or enforcement-versus-advisory mark; a redaction control present only as unread data, placed agent-side, or pattern redaction named as the defense against deliberate exfiltration; a control claiming a preventive grade it cannot hold today.

### Cost is knowable

Every methodology operation has a measurable cost, a breakdown, and a baseline, answerable as queries. The canonical questions — is 100k tokens a lot, what makes it up, how much was cached, would a rewrite reduce it — each have a recorded-evidence answer.

- Cost is denominated in native units: tokens by cache class, wall-clock, usage-window consumption, context occupancy. Dollars are a projection of the recorded native units through a declared billing context; under subscription auth the binding constraints are usage windows and operator time. The insight layer — waste, repetition, right-sizing, feedback latency, yield — is unit-independent.
- Token budget: every generated context artifact carries its token count at build time, and the pricing function (pure, in `vsdd-core`) emits a priced bill of materials — total, per artifact, cacheable portion — at session start from the composition and the stamped counts, before the spend. CI budget-gates each artifact class. Pricing is a distinct pure function; the composition function takes no token counts and cannot price.
- Records-based capture consumes the runtime harness's traces — usage by cache class, tool-use events, the recorded model dial, and the effort dial where the trace carries it (dispatch-primitive-dependent; the dispatch manifest is its reliable source) — plus crosslink's harvest and context measurement over that same state. No telemetry collector, no sink, no dashboard is deployed. Every figure carries provenance — recorded, measured, judgment, or could-not-check (the registered term; its standard neighbors are observed, derived, estimated, and no-data) — and an agent never reports a cost it did not observe.
- The cost-and-efficiency report is a reader over the traces, homed in `vsdd-core` beside the conformance verifier — pure over the records, surfacing unit economics with provenance on every figure; a reader over the records, not a persisted ledger. The telemetry apparatus — collectors, sinks, dashboards, a persisted unit-and-dollar ledger, calibration tied to dollar actuals — is retired, not built.
- Unit economics: cost per finding, per round, per phase, per slice, recorded in the tracker. Baselines update from the recorded actuals — token counts by cache class, not dollar actuals. Dispatch manifests declare the expected baseline, and the orchestrator compares actuals per result in-cycle.
- The optimization loop treats content rewrites as measured passes: token price down at constant finding yield is the win condition.
- Efficiency advisories are trace queries the AI Engineer domain owns, surfaced at session boundaries with numbers: repeated searches propose a crosslink knowledge page; repeated reference reads propose an index once the records show the repetition pays for it; cost-per-outcome by model tier and effort level by task class proposes tier and effort defaults in the review config. The rightsizing signals ship as versioned advisory data — up-signals: the rework ratio, cross-lens convergence density on one defect, a stalled finding series at stable scope; down-signals: repeated clean rounds from a lens, dismissal-heavy yield, and mechanical residue — each computable from the tracker, the plans, the traces, and git history, with no new capture. The advisory states its attribution grain per auth mode. Absorbable advisories execute; provisioning or tier defaults reach the operator with the math. Scheduled execution runs on crosslink sentinel; the advisories stay legible to crosslink's existing viewers — vsdd builds no viewer.

Falsification: a cost figure in any record without provenance; a composition whose token budget cannot be produced; a baseline with no linked recorded actuals after a completed cycle.

## Verification architecture (phase 1b)

Pure core (property-test and mutation targets; deterministic, no I/O):

The snapshot is an explicitly acquired materialized view, acquired in the effectful shell; the function never acquires. Properties: determinism; the degraded marker appears as a plain word exactly when the answer is degraded; truncation marked in words; absent fields render worded absences; the string's information survives color stripping.

Manual by design with a named owner: milestone conversion and ratification acts, oracle authorship, the per-slice manual-test checklists for operator-facing behavior, and the assistive-technology read of the human status form with a named screen reader.

Phase-5 candidates: mutation testing with a kill-ratio floor over the pure core; fuzz testing of the adopter-edited and tracker-sourced parsers (config, state, registry, exception register, runtime-harness settings, tracker payloads, install manifest, statusline repo-set config); property-based testing of the pure-core properties above; no proof execution.

Trust boundaries:
- Adopter-edited files — `.vsdd/config.yaml`, `.vsdd/state.yaml`, the vocabulary registry, the install manifest, the statusline repo-set config, and the exception register — are schema-validated at read by vsdd; any read failure yields a diagnostic, never a panic; an absent, malformed, or shape-invalid exception register never passes the deviations gate leg.

- Generated-context sources: routed and pinned; the generator consumes only routed artifacts.
- The runtime harness's consent surfaces (project trust, permission-bypass consent, per-action prompts, project-server trust, identity approval) are owned by the human. The dispatch approval is the operator's dispatch act; no orchestrating session provisions consent on the human's behalf, and the harness's refusal of such provisioning is correct conduct tooling respects. Identities enter trust before launch with key material provisioned, because post-launch approval under enforced signing is a race the operator loses.
- Trace actuals: provenance required on every figure (Cost is knowable).
- Dependency manifests: every added entry imports external code across the boundary and is governed by Dependency approval.
- The server-synced authorship basis: "verified over server-synced state" names exactly two load-bearing authorship anchors today — the `issue intervene` driver-key fingerprint (minted only on that local path) and hub-event signatures verified against the trust store in audit mode — and neither can distinguish a Solution Owner decision from an agent-authored comment at column level; every CI-leg check that verifies a decision over synced state is bounded by those anchors and carries the authorship sub-property as no-data until the signing-report regrowth lands (crosslink#73). Falsification: a check described as verifying authorship over synced state without naming which anchor carries it.
- The syntactic-versus-semantic rule: a schema or pattern pass is a shape fact about an artifact, never a truth fact about the system — truth-tier verdicts come only from evidence-consuming machinery (gates, the corroboration join, hash bindings) — and state semantics never encode into schema pairs. New check needs are decided in writing, in order: the scope test (markdown subject, document-anchored rule suppliable as data, shape-tier verdict — otherwise vsdd implements it and never raises it upstream); the support test (mdatron supports it today — wire it); the raise (in scope, unsupported — raised to mdatron as a generic primitive another consumer would want, carried meanwhile as a declared deferral with a retest trigger). Falsification: a semantic transition rule encoded in a schema pair; a record treating a verify pass as gate evidence; a check need executed with no recorded three-question decision.
- Governed-artifact prose never restates counts or enumerations the frontmatter carries — cite the field, never copy the value.
- Machine-identifying content — user-absolute paths, hostnames, personal names, key material or fingerprints — never enters commits, tracker records, or published text; machine-form outputs destined for those records render paths repo-relative.
- Output sanitization is the outbound peer of the inbound hidden-Unicode rule crosslink carries for web content; a shared primitive serving both is raised to crosslink as a non-blocking proposal, with confusable detection and mdatron's diagnostic stream named as companions.

Falsifiability instruments: the convergence fixture corpus (at least eight hand-authored mid-cycle repository states, each with its structured reference answer authored independently of the derivation and operator-adopted; isolation dispatches are preflighted dispatches like any other); the red-gate cheat fixture reproducing the layer-7 incident; the seeded fixtures per criterion, audited against each slice's falsification conditions at its phase-2a corpus audit.

## Decomposition (phase 1c)

Milestones are independently buildable and independently verifiable; a milestone may depend on an earlier milestone's behavior, never its internals. The ordering is a **walking skeleton**: the enforcement path is built end to end first — data through detection to a live self-governance control plus a CI backstop — as one genuine vertical slice (Slice 1), and the remaining capabilities follow as component-cohesive slices, each binding its own control at its true-dependency layer rather than deferring all enforcement to one gate layer. When an invariant's detection inputs exist, its detection and its available enforcement land together; its tamper-proof enforcement lands when its independent oracle exists.

**The engine** is the shared, already-built base every slice builds on, depended on through its behavior, never its internals — vsdd being the methodology harness, the layer that harnesses the agent to the methodology, distinct from crosslink beneath it and the runtime harness it runs on. In code: reading and writing `.vsdd/state.yaml`; the snapshot acquisition; the pure derivation and its integrity checks; the three renderings; the statusline wiring script; the output-sanitization cleaner. In data: the versioned sets more than one slice reads — the state schema, the composition vocabulary, the statusline data set, the branch-name grammar, the baselines and token budgets, the failure-kind enumeration. A data set only one slice reads is that slice's input.

**Guardrails and their grades.** A guardrail is a control that blocks or warns at the point of an act. Each is one of three honest grades: **detective** (reads real data and reports — `vsdd status`, exit 0, cannot block); **bypassable preventive** (a client-side hook that blocks locally but can be skipped, so it records a deviation rather than preventing it); **enforced preventive** (a server-side check the committing agent cannot skip — a required status check). Tamper-proof enforcement of a process invariant against an agent that controls the local tracker is beyond all three and requires an independent oracle the committing agent cannot author (CI over server-synced state; corroboration and adversarial review). Each guardrail is a thin wrapper over one shared implementation — the block logic lives in the vsdd binary and its data, the git-hook wrapper and the `vsdd init` payload wrapper differ only in wiring, and a conformance check flags divergence between them. The self-governance form is dogfooded in this repo; the shipped form installs for adopters.

**Slice obligations, stated once.** Each slice names the acceptance criteria it closes by their leading names (every criterion has exactly one closing slice or a declared split); carries its slice of the fixture corpus; owes at phase-2a entry its red-gate seed and, where it ships operator-facing behavior, the operator-authored manual-test checklist; wires the output-sanitization cleaner into any new agent-consumed or terminal surface as its own act; re-runs the fresh-container install-and-smoke check when it extends the install payload (oracle: every install-manifest entry resolves and `vsdd status` renders a working segment at exit 0); and authors a per-commit wall-clock budget when it binds a per-commit hook. Phase executions and slices are crosslink milestones; exits are boundary commits with milestone closes and typed result comments.
