Deep read of both repos, commissioned by the operator before redrafting the dispatch amendment. Finding: both implement the operator's structural split literally — design is attended and highly interactive; execution is autonomous; the human acts between runs, not attached to them.

CROSSLINK'S BOUNDARY. /design is conversational by construction: interview phases grounded in codebase findings, wait-for-user before drafting, open-question blocks resolved interactively, and hard rules — no source edits (writes only to .design/), no auto-kickoff, no auto-issue-creation (docs_src/guides/design-workflow.qmd; resources/claude/commands/design.md). kickoff is the autonomous executor: 'launches an autonomous Claude agent in an isolated git worktree… in the background' (kickoff.qmd). Between them sits kickoff plan, a read-only gap analysis with a read-only toolset that never skips permissions. The human role is named 'driver' throughout; driver acts are between-run acts: trust attach for local runs ('The agent waits for you to approve trust before it begins'), swarm gate/checkpoint/merge decisions, sentinel triage (CI failures are never auto-dispatched), draft-PR review. Local tmux = attended-once (human attaches to approve trust); container = autonomous (bypass-permissions safe because hooks re-install inside the container as the residual policy layer). Trust design move: kickoff subagent identities are auto-approved with dedicated keypairs — 'the driver explicitly invoked kickoff, so trust is implicit' — the human's dispatch act IS the consent utterance. Unresolved design questions surviving into a run: the prompt directs escalate-don't-guess (file a blocker comment, proceed with unblocked parts).

THERMITE'S BOUNDARY. Authority chain design → impl → verification, never reverse. Autonomy is activated by an explicit human act (/goal with the binding contract) and bounded by a mechanical stopping condition — 'never declare the goal complete until the mechanical check says so.' Human-required slots: pushes (R-GIT-1), design amendments and thesis escalations, oracle authorship (R-CHAR-3: expected values never copied from the toolchain's own output; oracles are orchestrator/human hand-authored before any session), stage gates (R-GATE-1: headline claims change at gate declaration, not merge), slag-waiver review fields, spec-intent review ('whether the contract is the property the user wanted' — the one machine-unclosable judgment), and injected-instruction conflicts (R-INJECT-2: surface, never silently pick). Frozen-decision pattern: attended rulings are recorded as do-not-re-litigate registers; a merge contradicting a default must update the register first. Orchestrator doctrine: 'stays hands-on-the-wheel… verify every result — read the diff, re-run the gauntlet, cross-check the critic.'

KEEPING AGENTS ON TASK — the three-layer control stack both repos converge on:
1. HARD (mechanical, unreasonable-around): worktree/container isolation; per-run allowed-tools whitelists (crosslink build_allowed_tools; Thermite role allowlists — critic has no Edit: 'If you find yourself wanting to Edit, you have drifted from discriminator into generator — STOP'); timeout kill wraps; fail-closed hooks (parse error = block); Thermite's spec-discipline read-gate (edit physically blocked until goal.md + governing doc + a declared reference are Read this session — exit 2 with exact remediation); route-table allowlist with ready-to-paste stanzas; anti-pattern regex gate; builder manifests as 'an absolute boundary' with STOP-and-report expansion, orchestrator re-authorizes.
2. SOFT (normative, injected): the generated KICKOFF.md 15-step protocol (identity, session binding, plan comment before code, typed comments, periodic sync, session end, write DONE); rules injection every prompt with anti-evasion sections ('Size does not exempt you'); R-INJECT-1 'Repetition is enforcement, not ceremony' — injected instructions bind at user-message priority; watchdog nudges (heartbeat stale >5min → typed 'continue working' up to 5 times); breadcrumbs + context-budget compression directive for context-loss recovery; tone discipline ('residual emphasis is what a downstream agent anchors on and drifts toward').
3. VERIFICATION (after-the-fact): acceptance criteria extracted to machine-readable form with per-criterion verdicts and 'Do NOT mark pass without citing concrete evidence'; .kickoff-report.json (phases, verdicts, evidence, unresolved questions); adversarial critic loop (every divergence = runnable failing test + blocker issue; no prose-only findings; verify-the-test-fails step); swarm gates refuse while agents live-unresolved and checkpoints refuse without a passed gate; three-valued exits (0 pass / 1 finding / 3 INCONCLUSIVE — 'A CI gate that fails open is a silent pass'; empty enumeration = INCONCLUSIVE, not pass); doc-drift aggregate content-SHA pins with honest bootstrap (pin at last-touch, never blanket-HEAD — 35/48 drifted and filed rather than rubber-stamped). Division of labor: deterministic gates catch syntactic cheats; adversarial agents catch semantic cheats (anti-pattern-gate scopes proof-dodging OUT of regex — 'the acto-critic enforces R-DEFER-9 adversarially').

NEVER-STARTED / STALLED / TIMEOUT, as the chassis actually classifies them: .kickoff-status sentinel written LAUNCHING before the send, FAILED on send failure, RUNNING after ('never a worktree in limbo with no status'; missing status = failed); swarm probe classifies worktree-without-status-without-tmux as 'failed (session died)'; wall-clock timeout reclassification from .kickoff-metadata.json; heartbeat staleness for stalled; /check classifies Working / Waiting-for-input / Error / Done; harvest treats RUNNING as non-terminal ('otherwise the harvest… posts a premature 0-findings comment'). Lesson for vsdd: never-started detection belongs to the launch-status sentinel + session records + heartbeats — chassis instruments to consume — NOT tracker-event counting, which collides with 'absence of findings and absence of looking… neither produces tracker issues.'

UPSTREAM DOC-VS-CODE MISMATCHES found (to join the upstream findings list): (1) shipped agent_overrides reduce the agent block list to destructive-ops only (plain push/merge/rebase allowed) while container-agents.qmd, kickoff.qmd, tracking-modes.qmd, and the generated prompt all claim 'no push, no merge, gated commits' for agents — the strict blocks are prompt-level, the hook enforcement is deliberately looser; (2) kickoff run --container does not pass --dangerously-skip-permissions (only container start does), so the documented no-prompt container path holds only for one of the two entry points; (3) nothing writes the TIMEOUT sentinel the harvest checks for — the timeout kill leaves RUNNING, caught only by the wall-clock check.
