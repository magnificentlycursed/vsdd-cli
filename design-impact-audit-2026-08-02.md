## Design Specification

### executive summary

**Counts per class:** 38 findings — 11 CORRECTION, 17 ADOPTION, 5 RE-SCOPE, 5 NO-CHANGE-CONFIRMED (plus confirmations folded into rows where a finding carries both a confirmation and a carry).

**What blocks anything (3 items, none blocking currently-open Phase 1 build work):**

1. `swarm-review-emits-plan-only` (RE-SCOPE, blocks-a-phase) — Phase 5's exit act as worded ("a `crosslink swarm review` run with findings filed") is unexecutable on the built surface: `swarm review` writes a plan to the hub and launches no agents (source-verified at mirror HEAD). The swarm-fallback open question is the sanctioned rescope home; Phase 5's 1b must name the actual driver.
2. `corroboration-substrate-narrower-than-design-language` (RE-SCOPE) — the deviations-gate CI leg's "verifies dispositions over server-synced state" and the Design-doc lifecycle member's disposition check rest on a substrate the grounding shows is narrower than the language: `comments.author` is self-declared everywhere, `driver_key_fingerprint` exists only on local `issue intervene`, signing runs `audit`, and the v2 signing report was retired upstream (#754). Blocks the CI leg's **target grade** as described, not the local gate.
3. `self-re-arm-refusal-mechanism-underspecified` (CORRECTION) — the remediation AC-5's "the decidable substrate exists — crosslink comments carry author and driver_key_fingerprint columns, server-synced" overstates: the fingerprint column is populated only on the local `issue intervene` path (REST writes None), so an SO `decision` comment carries no fingerprint. The self-re-arm fixture cannot be built as parenthetically described; Phase 1's 1b must pick a real mechanism.

**The 5 highest-leverage adoptions:**

1. **Families tri-state + non-vacuity + `--deny-warnings` CI gating (#855, execute now)** — the 2.1.0 envelope makes "a required family actually ran" assertable today; no consumer of `verify --json` exists anywhere in vsdd's wiring, and `--deny-warnings` (shipped at vsdd's own request, mdatron #121) is used nowhere. Zero build, closes the silent-family-death and vacuous-clean gaps this estate's own #822 incidents motivated.
2. **Reviewer roles as `.claude/agents/` agent types (Phase 5)** — `tools`/`disallowedTools`, per-lens `model` + `effort`, `skills:` full-content preload, and per-agent `memory` deliver critic-lacks-Edit, the dials, and construction-grade injection natively. `.claude/agents/` does not exist in this repo; the contract's "awaits the dispatch-parameter seam" framing is stale on this path.
3. **Consume the upstream cost substrate (Phase 6)** — `token_usage` (schema v15), `timer`/`time_entries`, `swarm config/estimate/harvest/plan`, `context measure`, `sentinel_runs`/`sentinel_dispatches` are built and unconsumed; the leverage-versus-build rule says consume, not rebuild, and none of them appear in Phase 6's dependency list today.
4. **The mdatron routes/pin/citation families are already shipped at the pinned 0.5.0 (Phase 4)** — the build-plan's "each family gates on the mdatron release that ships it" is a satisfied dependency for those three families; arming them is wiring work now, and the hand-rolled Decomposition content-hash pin has a shipped engine home (whole-file today, section grain riding mdatron #146).
5. **Turn on the shipped control-plane rungs** — `crosslink workflow diff --check` + `crosslink context check` in CI (the Thermite settings-clobber class, their control-plane meta-gate pattern, catchable today), and an adopt-or-decline ruling on `agent flags --strict` as a PreToolUse hook — the one enforcement-grade rung the estate can enable without building anything.
