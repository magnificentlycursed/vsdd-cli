**Authority chain and how decisions are recorded**

- The umbrella is the top of the chain below the human: its "Open questions" section says defaults "may be changed only through a reviewed design amendment before their relevant interface freeze"; "Parallel-work rules" §4 requires "an architecture note, compatibility/proof impact, and downstream workspace verification" for changes to `peritus-types`, `peritus-spec`, `peritus-kernel`, `peritus-policy`, public protocols or the TCB; the ownership registry says "changing ownership requires a plan amendment".
- Slice docs are "frozen" before parallel implementation and the freeze is a commit of its own: `d2b12bdc design(d2): freeze production review engine boundary`, `07b40817 design(d3): freeze scheduling and AcTor boundaries (#19)`, `fef4f065 docs(e1): freeze harness materialization design (#20)`, `badcc916 docs(e2): freeze debugger design (#21)`, `de8d74ae docs(e3): freeze production evaluation design (#22)`, `a66deaf0 docs(f0): sign evolution architecture (#23)`, `b7578998 docs(design): freeze B1 authority foundation`. B2 and D1 docs were committed inside the implementation commit instead (`c135d3b2`, `50eb2ad5`).
- Decisions are recorded as hub comments of kind `decision` (767 of 3,300 comments) and `plan`/`result`, e.g. hub #6: "Architecture verdict: proceed with B2 before B0 ... alternative B0-first ... is rejected"; and in each design's "Architecture verdict" section (umbrella: **ready**; benchmark remediation: has its own verdict section).
- What keeps the documents honest mechanically: (a) `architecture.toml` is enforced by `cargo xtask architecture-check` inside `cargo xtask all` and Gate A; (b) the verification manifests are validated by `cargo xtask verify-trust` and the proof-impact rule that "a transition is accepted only if its exact approved record already exists unchanged on the protected Git base" (verification/README.md, "two-step rule prevents a source edit from approving its own review record"); (c) the GitHub ruleset template `docs/formal-governance-ruleset.template.json` and the canonical workflow copies under `xtask/src/reproducibility/canonical/` are compared byte-for-byte (`github_ruleset_policy.rs`: "restore the canonical template byte-for-byte; changes require independent review"); (d) `docs-check` for the docs tree. Design Markdown itself is **not** hashed or gated (verification/README.md lists "design Markdown" among the files that may change in an authorization-only commit) — the design docs are kept honest by review and by the freeze-commit convention, not by a checker (**inferred** from the absence of any design-doc check in `xtask/src/*.rs` names and `xtask all` descriptions).
- Umbrella amendments during build: 5 commits after creation (`6eeb31cf` 08-21 "align implementation dependency graph", `b35f336d` 08-23 B1 scaffold, `c6a3c7c9` and `2f2358fc` 08-27 H-waves, `cd4a09ec` 08-30 H1 operator); each is tied to the slice issue in the subject (`(#27)`, `(#31)`).

### 2a Test Suite Generation (red gate)
- **Not observed as a separate phase.** Tests, proofs and implementation land in one commit per slice (PR #4 B2: 67 files; PR #21 D2: "18 focused peritus-review tests, 17/0 D2 Verus proofs" in the same 87-file commit 0345ee2). No hub comment or PR body claims that a test suite was written and shown failing before implementation; the phrase "failing (regression )?test" occurs in 2 of 3,300 comments.
- What exists instead: (a) the umbrella's test design rule "Every bug fix begins with a failing regression test at the narrowest meaningful boundary" and proactive-bug-discovery R6 "demonstrate the regression fails before the fix and passes afterward", honoured in later fix commits ("Verified the reproduced retention fault with a deterministic regression", cfd2267f; "Verification: baseline reducer failure, real permission-injection/restart/retry acceptance", e703ce41); (b) adversarial/negative test catalogues written into the slice spec before implementation (b2 "Verification target"; umbrella rule "Every proof invariant has at least one negative executable/property test that would fail if the guard disappeared"); (c) A2 conformance catalogues and fixtures that consumers must satisfy ("Shared protocols/specifications land before their consumers. Consumers use conformance fixtures and fake implementations", Parallel-work rule 2; PR #2 "establish A2 conformance foundation").
- Gate: mutation testing is the mechanical substitute for "tests that would pass anyway" (`bug-discovery.yml` `mutation` job weekly; PR #71 "isolated cargo-mutants campaigns covering 32 receipt and 23 cancellation mutants ... 18 caught, 5 unviable, 0 missed").

### 2b Minimal Implementation
- Practised as *complete* implementation, explicitly not minimal: umbrella "No stage is an MVP"; Parallel-work rule 6 "placeholder success paths and `todo!()` in reachable production code are prohibited"; `.chainlink/rules/rigor.md` "Every function body must contain a working implementation"; `post-edit-check.py` scans every edit for TODO/FIXME/`todo!()`/`unimplemented!()`/empty bodies; pre-commit audits in hub results ("no placeholders, debug residue, ignored tests, credential patterns, executable files, or binary artifacts", PR #35).
- Producer: worker agents under frozen path ownership ("Workers do not edit shared files and do not run workspace-wide verification", d2) with the root integrator owning manifests, `architecture.toml`, generated assets, Git operations and every verification command; builds serialized (`CARGO_BUILD_JOBS=1` "because the development host has full swap", d2).
- Gate: focused checks then `just gate-a` (Gate A) locally, then hosted Gate A on the PR, then Gate A again "at the exact merged main commit" (b2 Verification target; hub #18 "serialized fresh-main CARGO_BUILD_JOBS=1 just gate-a passed").
- Record: signed commit with a "Verification:" paragraph; hub `result` comment with the commit hash and test/proof counts; PR body "Verification" section.
- Examples: hub #45 (S2) "Pre-commit gate passed for S2: exact 37-file scope; focused and full workspace tests green; ... Verus no-cheating 183 obligations plus 6 gate proofs"; PR #19 body; hub #66 shows the worker/root split in action (P1-P7 workers in `feature/workbench-pN` worktrees, "Root owns integration/native acceptance/final commit-push; no phase implementation by root while workers run").

### 3 Adversarial Refinement
- Artifact: an "independent final review" of the exact tree by a separate model/agent before the signed commit, producing typed findings; for formally governed changes a detached verdict record (`verification/reviews/PCR-NNNN.toml`) with `FINDING-NNNN` rows (`severity`, `blocking`, `disposition`), retained per-package gate outputs and a mandatory `review-report.md` ("an empty findings array is never the only retained evidence for a no-findings verdict", verification/README.md).
- Reviewer identity and freshness: `verification/actors.toml` registers 9 actors: 3 `crosslink-agent` owners (SSH-key principals) and 6 `codex-subagent` reviewers whose principals are session/task paths, `mode = "read-only-review"`, `model = "gpt-5.6-sol"`, `reasoning_effort = "xhigh"` (actor-provenance.json). "Every new authorization enrolls a fresh independent reviewer ... No historical reviewer identity is reused for a different agent" (verification/README.md). Hub #3: "Independent GPT-5.6 Sol xhigh exact-tree review verdict: READY to commit; no Critical/High/Medium/Low findings"; hub #5: "independent read-only Sol xhigh final review active". Model diversity is thus Claude-side root/workers (the `.claude/` hooks and `Sol xhigh subagents` wording, **inferred**) versus a GPT-family reviewer, matching the whitepaper's "different model family" note.
- Rounds and stop rule: one full review → scoped repair by the owning worker → "bounded re-check" by the same reviewer of the repaired tree → Gate A (hub #6: "The same reviewer passed the bounded re-check: review cycle IDs/ordinals are coherent, every current waiver is validated ..."). The whitepaper's hallucination-based termination is replaced by "no blocking findings remain + every gate passed" (verification/README.md: "An approved PCR requires an approving verdict, every gate passed, and every declared blocking finding fixed, invalid, or superseded").
- Other adversarial inputs: ontological review hub #95 (read-only, external report); proactive bug discovery (fuzz, mutation, chaos with "Daybreak Blue" subagents whose "suspected failure windows are hypotheses to test, not confirmed bugs", `.design/proactive-bug-discovery.md`); H0 security red-team shards (`security-qualification.yml` "eight candidate-bound workers"); external benchmarks used as diagnostics with a "non-cooking" rule (`docs/benchmark-integrity-appendix.md`); the 2026-10-06 "daily-driving limiters" audit that generated 719 hub issues `[L003]..[L858]` (label `daily-driving-limiter`) from one source document.
- Examples: PCR-0005 (reviewer ACTOR-0004, 4 high blocking findings all `fixed`, FINDING-0001 "host permission admission"); PR #88 "PCR-0007 ... Findings: six blocking findings fixed"; hub #18 "D2 QA and pre-commit review passed ... QA verdict pass; no confirmed defects remain".

### 4 Feedback Integration
- Routing: findings go back to the owning worker, scope held constant ("The two owning agents are repairing those scoped causes; no B2 scope expansion", hub #6). Dispositions are the closed set fixed / invalid / superseded (PCR) and, in the product's own review engine, fixed / disputed / superseded / waiver-requested (umbrella "Writer, reviewer, and fixer orchestration"). Spec-level feedback returns as a design amendment commit on the slice issue (umbrella amendments `(#27)`, `(#31)`; `f962195c docs(design): record remaining product split (#99)`).
- Larger loops: benchmark failures → `benchmarks/external/failure-journal.md` → `.design/benchmark-failure-remediation.md` (S0-S9) → PRs #40-#45; GitHub bug reports → omnibus fix commit `94f24adf` "Address GitHub #98, #91, #80, and #68 ..."; live human TUI audit (hub #98) → hub #99 (196 comments) → PR #105 (60 commits); limiter audit → L-issues → "minimum repair" rounds (hub #826 "Scope remains EXACTLY the existing 20 minimum repairs", PR #113 draft).
- Waivers: policy exists (h4-release-policy: only non-release-blocking findings, "from an authority other than its reporter"); no granted waiver was observed in the sampled records.

### 5 Formal Hardening
- Not a late phase: Verus proofs are produced with each slice from A1 onward (hub #3 "188 crate proofs", PR #3 obligation counts, PR #21 "17 verified, 0 errors") and verified under `--no-cheating`; `peritus-tcb` is the sole trusted boundary with an empty baseline (`verification/exclusions.toml` `entries = []`). Fuzzing, mutation and chaos arrived later as a dedicated campaign (`.design/proactive-bug-discovery.md`, PR #71, `bug-discovery.yml`). Proof-coverage closure work is tracked as "GAP" issues/PRs (#75-#78 "Close GAP-03 scheduler production proof gaps", "Close GAP-04 context and resume proof correspondence") with 917 evidence files under `docs/formal-coverage-evidence/`.
- Gate: Gate A `verus-shards` (`verus-verify-strict` operation) + `verus-policy`; `formal-authority.yml` evaluates proof-impact trust against `PERITUS_PROOF_IMPACT_BASE`; PCR two-step authorization (authorize PR, then apply PR: PR #75 → PR #76, PR #88 → PR #89/#90).
- Record: `obligations.toml` statuses (all `in-progress`; "Nothing in this file claims discharge until a registered independent reviewer approves"), PCR ledger (8 approved PCRs: 0001-0004 2026-08-21/22 genesis, 0005 09-10, 0006 09-13, 0007 09-16, 0008 09-17), CHANGELOG 0.0.3 "Expand formal coverage for scheduler cancellation ...".

### 6 Convergence
- Slice-level exit: Gate A green locally and hosted on the PR, independent review with no blocking findings, signed merge, Gate A re-run on fresh `main`, changelog PR, hub issue closed with a `result` comment ("Closure complete", hub #18). Product-level exit is a verified policy: `docs/h4-release-policy.md` reduces 25 criteria / 44 evidence requirements to `Ready` or `NotReadyForProduction`, requires "at least two clean approvals ... producer-independent, distinct reviewer identity, distinct fresh-context digest", and `release/README.md` ships only `not-satisfied` templates. The umbrella Status still says "H4 release decision pending"; the five shipped releases (v0.0.1 PR #51 2026-09-07 … v0.0.5 PR #111 2026-10-03) are explicitly pre-qualification ("Full production qualification remains governed by the H4 evidence gate", CHANGELOG 0.0.5), which departs from the umbrella's own rollout rule "No public alpha/beta package, installer, release tag ... before the complete production acceptance checklist passes".
- Hallucination-based termination: **not observed**; termination is finding-set-empty + gates green.

### 3. roles and dispatch shape

### 8. divergences from the whitepaper, and practices it does not mention

Divergences (whitepaper → Peritus):
1. **Red-before-green TDD core is absent.** The whitepaper's central constraint ("No implementation code is written until a failing test demands it", Phase 2a red gate, 2b minimal implementation) is not practised for slice delivery: tests, proofs and code land together, and the rules demand *complete* rather than minimal implementations. Failing-first is applied only to bug fixes (regression rule) and verified indirectly by mutation testing.
2. **Spec review by the Adversary before tests (1c) is not observed.** Designs are self-frozen by the root agent with the human; the adversary reviews the exact *implementation tree*. Later semantic review (hub #95) happened after months of code.
3. **Adversary tone and termination.** No "Sarcasmotron"/negative prompting or hallucination-based exit; the reviewer is a read-only GPT-family subagent producing typed, evidence-bound findings, and the exit is "zero blocking findings + every gate passed", recorded as a content-addressed verdict with a mandatory review report.
4. **Human role.** The whitepaper's human signs specs and arbitrates; here the human mostly approves commits/pushes/secrets, redirects dispatch, and does not review PRs on GitHub (ruleset: zero approvals; 0 reviews on 91 PRs).
5. **Formal hardening is first, not fifth.** Verus proofs and the trust boundary exist from A1 and gate every PR (`--no-cheating`), rather than being "executed against the battle-tested implementation" after Phase 4. Fuzz/mutation/chaos did arrive later (PR #71), matching Phase 5's second half.
6. **Chainlink beads per spec item** (whitepaper: sub-issues for each contract item, edge case and provable property) → one hub issue per slice/campaign with proofs tracked in `obligations.toml` (`live_issue`), not as sub-issues; the only mass per-item issue creation is the 719 limiter findings.
7. **Convergence**: the four-dimensional "Zero-Slop" exit is replaced by a verified release-policy reduction (H4) that has not been reached, while releases ship anyway as pre-qualification builds.
8. **Verification tooling**: Verus (not Kani/CBMC/Dafny/TLA+); no Wycheproof/Semgrep observed; cargo-deny/`cargo vet`/`cargo audit` for supply chain.

Practices the whitepaper does not mention:
- Parallel-ownership decomposition (frozen per-path worker scopes, root integrator, serialized builds, bounded worker concurrency) and worktree isolation.
- Machine-checked review ledger: actor registry with provenance, PCR change records with raw-byte source fingerprints, detached signed verdicts, retained gate outputs, "every new authorization enrolls a fresh independent reviewer", two-step authorize-then-apply PRs, and CI that refuses self-approving edits.
- Architecture-as-policy (`architecture.toml`: layers, verification classes, owner slices, line limits, forbidden module names, owned exceptions) enforced by `xtask`.
- Reproducibility policy: canonical workflow copies, ruleset template, justfile, deny, actionlint, pins and timeouts compared byte-for-byte in CI.
- Hook-enforced tracking (issue-before-edit, git mutations denied to the agent, stub detection after every edit, rule injection on every prompt) and SSH-signed per-agent hub event logs with lock claims and handoff comments.
- Evidence discipline: "no implicit success" everywhere (gates fail closed, timeouts never accept, placeholders scanned), benchmark non-cooking rule with an integrity appendix, frozen benchmark campaigns, evidence kept outside Git, release templates that are deliberately `not-satisfied`.
- Design-time merge gates per wave (Gate A..H) and a self-contained "Architecture verdict" in each design.
- Visual-design finish review (`.impeccable/`) for the WebUI.
