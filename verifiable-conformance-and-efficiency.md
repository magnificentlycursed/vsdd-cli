# Feature: Verifiable-conformance + efficiency subsystem

## Summary
The meta-harness must **prove, from the run record, that its own disciplines fired for every dispatched agent** — the phase-appropriate primer, composed domains, and supplements were loaded; the intended tools were used; the run was right-sized (cache, model/effort, targeted reads). "Availability is not activation" (contract §133) is already ratified law; this subsystem **mechanizes** it, turning cargo-cult performance (personas that ship as files nobody loads) into verified conformance. **Verifiable conformance is the center of gravity; efficiency/right-sizing is one axis under it** (operator ruling 2026-07-31). This is a spec amendment: it supersedes `DESIGN-OBSERVABILITY.md`, re-scopes "Cost is knowable" (§140-153), and re-grounds the AI-Engineer domain from observability-lens to measured right-sizing/conformance judge; Red Team is re-pointed at control circumvention.

**Founding evidence (two live instances, not hypothetical):** (1) the #821 cold-review lenses read no `vsdd-domain-*` persona — they got their lens from the dispatch prompt, not the files (recorded in `wf_0ac03bda-2ee` transcripts). (2) *This cycle's own opening* bypassed the personas — the orchestrator dispatched a general-purpose subagent with a paraphrase of the composition until the operator caught it; the correct path (load the files) was not the only path, and the catch was **human, not mechanized.**

> **STATUS — the subsystem is 0% built (grade-honesty banner, applied reflexively per REQ-22's could-not-check bar).** Every *Grade* line in the requirements below states a **target** grade — the enforcement grade the built control will carry. The **current** grade of every REQ is **convention / hand-audit** (the bootstrap interim, REQ-17): none of the composition function, the conformance verifier, the efficiency engine, the exercise-registry, the dispatch preflight, the session-start hook, or the fan-out gate is built, so **no "preventive-terminate / CI-backed block / fail-closed" claim below is in force today.** Read every target grade as "*target* (current: convention/hand-audit)". Where this doc asserts a control's behavior that cannot be checked against a built artifact, the honest status is **could-not-check**, never clean — the doc's own REQ-22 discipline, applied to itself (and to the record-capability claims this doc rests on, which are runtime records not committed to the repo: see C8/REQ-14 provenance).

## Requirements

**The governing law (operator ruling 2026-07-31): *authored is not exercised* — the sibling of "availability is not activation" (§133).** §131's installed-artifact manifest proves a mechanism is *installed*; this subsystem proves it *fired*. Every control the methodology authors must emit a provable "it ran" trace, audited against a **registry of authored controls + their expected-fire proof** (the exercise-layer twin of the installed-artifact manifest; a control lands in the tree paired with its fire-check, the same discipline as "artifact + manifest entry land together"), and **fails loud on authored-but-never-exercised.** Three properties make this law falsifiable rather than a liveness check (QE — "it ran" ≠ "it can fail"):

1. **Negative-case fixture, not an it-ran trace.** Each exercise-registry entry pairs the control with a **committed negative-case fixture** that proves the control is *non-vacuous*: it **fires on a known-bad input AND stays clean on a known-good input** (the #825 canary / mutation-kill discipline generalized to every control — schema, validator, gate, check). An entry carrying only an "it executed" trace, with no bad-case that trips it, is **vacuous** (theater that always passes) and fails the audit.
2. **Independent census, not self-registration.** Registry *completeness* is keyed to an **independent census**, not to the registry's own entries — otherwise an authored-but-unregistered control is undetectable. The census is the **installed-artifact manifest (§131)**, or a **build-break** that fails when a control-defining construct (a gate leg, a hook, a schema) emits no registry entry. A control present in the census but absent from the registry fails loud.
3. **Occasion-predicate, not blanket-expect.** Each entry declares the **occasion** on which the control is expected to fire (the triggering condition). A fire is expected **only when the occasion is present**; when the occasion is **absent**, the honest status is **could-not-check** (checks-run-clean ≠ checks-dormant), **never clean** — so a control that never had a chance to fire is not silently counted as passing.

REQ-1..23 below are instances of this law; the audit surface it governs (mechanism → proof-it-fired → fail-loud condition → home): **skill** → invocation record (REQ-16, this subsystem); **hook** → hook-trace vs git history (§133/§136); **CI check / required gate** → the check *ran*, not merely passed (this subsystem; the mis-wired-required-check case); **tool/affordance** → tool-call vs hand-roll (REQ-5/§130); **schema/validator** → validated non-vacuously (generalize the #825 canary); **composition** → computed not echoed (Slice 2/REQ-9); **preflight** → record precedes dispatch (§116); **dispatch manifest** → recorded + round-parity (Slice 6); **red-gate/pins** → executed-pin (Slice 4); **routing** → filed routing (Slice 1, live); **read-gate** → Reads precede the edit (§133); **dials** → recorded (REQ-7); **signing** → signed where configured (§116); **session-start (operator session)** → session-start-hook-fired + session-skill-invoked (REQ-19, this subsystem); **milestone (mid-cycle)** → a crosslink milestone created-and-active for the layer/slice, audited against the mandate + the designed-but-unbuilt mid-cycle-without-milestones detector (REQ-20); **tracker (search-before-create)** → an issue-search recorded before a new issue is created (find-or-create), not create-first (REQ-20); **anonymization/redaction** → the `check-anonymization` pre-commit hook fires over the shipped patterns, and sync-side redaction forms part of the corroborated copy (REQ-23). Scope discipline (SO): the built/other-slice rows are *referenced*, not re-owned; this subsystem newly contributes the abstraction (the law + the exercise-registry) and the uncovered cases (skill-invocation, dispatch conformance, composition-computed, CI-ran-not-just-passed, operator-session, mechanism-per-control). The canonical mechanism → proof → fail-loud → home table is preserved durably in the `run-record-capability-and-audit-surface` knowledge page.

Each conformance invariant is a **control**, stated as: mechanism · enforcement-ladder grade (**current → target**) · falsifier · the Red-Team bypass it closes. The **enforcement ladder** is the grounded methodology-harness ladder: **convention < friction < CI-backed block < harness-level capability restriction**. The **top rung is harness-level capability restriction** — the outer harness the checked agent *cannot reach* (e.g. a critic that structurally lacks Edit; a PreToolUse deny the agent cannot disable) — **not** "injection-by-construction": injection makes the composed context *present*, but a motivated in-harness agent can still ignore or route around injected context, so injection is a strong CI-backed/friction rung, not the ceiling. Prose is convention grade (the bottom rung, the vibes that cargo-culted) and is never the delivery form.

**Notation (one-time gloss).** `WAS` and `SHOULD` throughout are **set names** — the *observed set* (`WAS`) and the *required set* (`SHOULD`) — **not** RFC-2119 keywords; the required (`SHOULD`) set is **mandatory**, and `WAS ⊇ SHOULD` is set-superset containment. **Canonical record name:** the conformance-oracle record is called the **run transcript** (`agent-<id>.jsonl`) throughout; drifted phrasings elsewhere ("harness transcript", "the record", "run record") name this same artifact. The lifecycle index `journal.jsonl` is a **distinct**, **harness-produced** file (an agent-lifecycle event log the **agent cannot author** — the same append-only harness-produced property as the transcript), but it is **not the conformance oracle and not read as WAS / efficiency-engine substrate**: the verifier and efficiency engine read **only the run transcripts** for the WAS and the efficiency dimensions. Pinning both facts removes the prior contradiction (a "not the oracle" file elsewhere phrased as trustworthy "agent-cannot-author" substrate): it *is* harness-produced, and it is *not* consumed as conformance/efficiency substrate. The full record inventory lives in the `run-record-capability-and-audit-surface` knowledge page.

**Dispatch interception model (C5 — where vsdd can *prevent* vs only *detect*).** vsdd's preventive controls (preflight fail-closed / preventive-terminate) hold **only at the interception points vsdd actually sits on**: the `vsdd dispatch` command, crosslink's `kickoff` / `swarm` preflight (§108), and the git / CI operations vsdd gates. A dispatch routed through those points can be terminated *before it runs*. **The native in-harness spawn path — the Claude Code `Task` / `Agent` primitive — does NOT pass through vsdd** (it is the path this very cycle used), so vsdd-layer control over in-harness dispatch is **detective (post-hoc audit over the run transcripts), not preventive**. Making the native path preventive requires a **harness-level `PreToolUse` deny hook** that intercepts `Task` / `Agent` and redirects to `vsdd dispatch`; that hook is an **outer-harness dependency** (the harness the checked agent cannot reach — the top ladder rung), **not an achievable vsdd-layer control**, and is named as a dependency, not claimed as built (its arrival is also gated on operator-set branch protection, an operator dependency). Accordingly, every "preventive-terminate at preflight" grade in REQ-2/3/4/7 below is **scoped to the interception points above**; on the native path those same controls are **detective now (target: preventive, via the outer-harness hook dependency)**. "Correct path = only path" therefore holds **by construction only where vsdd is the interception point**; on the native path it is a **target contingent on the outer-harness hook**, not a present property.

- **REQ-1 — Phase is recorded.** Every dispatched agent's run carries the phase it executes, sourced from the state artifact / crosslink session breadcrumb (§37), not self-asserted. *Grade:* recorded (verification-only). *Falsifier:* a dispatch whose record names no phase, or a phase disagreeing with the milestone state. *Bypass closed:* run "phaseless" and claim any discipline post-hoc.
- **REQ-2 — Phase primer loaded (missing → terminate).** The phase primer for the recorded phase is present in the dispatched agent's context **by injection at dispatch**, delivered by the golden-path dispatcher (`vsdd dispatch`, below). A dispatch whose composed context lacks the required primer **fails the dispatch preflight (§108, fail-closed) and is terminated before it runs**, with a message routing back to the golden path — not launched-then-flagged. Verified after by a Read/injection event for the primer in the transcript. *Grade:* preventive-terminate at preflight (the mis-invoked agent never proceeds) + CI-backed verification backstop. *Falsifier:* a run that executed without the required primer present. *Bypass closed:* inline the primer's content in the prompt (no Read recorded); read-then-ignore (residual → cold review, REQ-13); dispatch raw `kickoff` bypassing the composer (→ preflight terminates it).
- **REQ-3 — Composed domains loaded (missing → terminate).** The domain personas the composition function requires are present by injection; a dispatch missing any required domain **fails preflight and is terminated**; verified after `Reads ⊇ composition-required domains`. *Grade/falsifier/bypass* as REQ-2. *Bypass closed:* load fewer/wrong domains; paraphrase them in the prompt (the #821 + this-cycle failure — the exact live evidence).
- **REQ-4 — Supplements loaded (missing → terminate); three-tier activation.** The supplements in scope are present by injection; a dispatch missing an in-scope supplement **fails preflight and is terminated**; verified after. *Supplement activation model (governed-corpus edit in scope, Part 2):* three tiers — (1) **runtime-determined always-on** — `claude-code-cli` whenever runtime = Claude Code, and `bash` for **every** agent (the shell is load-bearing for all agents — 91 Bash calls in the #821 run prove it); (2) **project-determined always-on** — `rust` for this Rust project; (3) **task-determined** — per surface (`github-actions` / `json` / `markdown` / etc.). The composition SHOULD includes the runtime + project supplements **unconditionally**; task-determined supplements enter the SHOULD only when their surface is in scope. *Gap named:* current supplement frontmatter gates by `languages_or_interfaces` only — there is no runtime-determined-always-on tier — so adding that tier is a governed-corpus edit in this amendment. *Grade:* preventive-terminate at preflight + CI-backed verification. *Falsifier:* a dispatch missing a runtime/project always-on supplement (even with no task surface named), or missing an in-scope task supplement. *Bypass closed:* skip; wrong-language supplement; treat a runtime/project always-on supplement as task-gated and omit it.
- **REQ-2/3/4 golden path — `vsdd dispatch`.** The composer that assembles the composition (SHOULD) into the dispatch and injects it by construction is the **path of least resistance** — the easy, one-command way to dispatch — so agents naturally take it; a raw `crosslink kickoff` that skips it carries none of the vsdd layer and **fails preflight (REQ-1..4/7) because crosslink's kickoff preflight is an interception point vsdd sits on**. Correct path = only path **where vsdd is the interception point**; the **native `Task`/`Agent` spawn bypasses this entirely** and is caught only by the post-hoc transcript audit (see the dispatch interception model) — making it "only path" needs the outer-harness `PreToolUse` deny hook (a dependency, not built).
- **REQ-5 — Intended tools used; no hand-rolled affordance.** A methodology act uses its mapped tool/affordance (act-to-affordance map §130); a Bash string re-implementing a mapped affordance is a flagged nonconformance. *Grade:* CI-backed detection. *Falsifier:* a hand-rolled equivalent of a mapped affordance with no stated reason (§130's own falsifier, now checked). *Bypass closed:* hand-roll the tool's job in shell to skip the tool and its checks — must also make the tool the path of least resistance (RT: correct path = only path). (Generalized to every mechanism in REQ-20.)
- **REQ-6 — Cache leveraged; warm handoff.** Shared context is passed to a dispatched agent as a warm slice, not cold-reloaded per agent; verified by a **measurable proxy** (AIE) — literal "same base-context bytes" is **not** provable from token counts, so the proxy stands in: **sibling agents under a shared parent with overlapping `Read` `file_path` ranges each posting high `cache_creation_input_tokens` rather than `cache_read_input_tokens`** is the cross-agent redundant fresh-load signal; where even the proxy cannot be established the figure is **advisory**. *Grade:* by-construction in the dispatch primitive + detection. *Falsifier:* N cold agents each `cache_creating` the same base context. *Bypass closed:* cold-reload anyway (AIE sycophancy mode: "sub-agent re-loads context the parent already has"; "prompt-cache hit assumed across 5-minute TTL boundary").
- **REQ-7 — Model + effort specified (presence is a hard gate at the manifest; appropriateness is advisory).** Every dispatch **manifest** (the `vsdd dispatch` / kickoff parameters) records explicit model and effort dials; unspecified dials **fail closed at dispatch preflight** (§91 "never inherited") and terminate the dispatch. *Capture-source correction (C8):* the presence gate reads the **dispatch manifest, not the transcript** — a preflight check runs *before* the run's transcript exists, so the dial's authoritative source is the `vsdd dispatch` / kickoff **manifest parameter**, not a transcript field. (*Effort's presence in the record is **dispatch-primitive-dependent** — record-verified this cycle:* it **IS** present in Agent-tool sub-agent transcripts (`agent-a5e20d9b`: `effort:high` recorded 24×; 139/141 effort-bearing files sit under `subagents/`) but is **absent from a crosslink-kickoff sub-agent record** — so the **reliable capture-source is the dispatch manifest**, with the transcript a **sometimes-available backstop**; effort is **could-not-check only when the record actually lacks it**, never asserted absent as a blanket. Either way, the preflight gate's source is the manifest on timing grounds.) *Primitive reconciliation:* the native Claude Code `Task` / `Agent` primitive **carries no model/effort at spawn**, so dial-presence is enforceable only at the `vsdd dispatch` / kickoff manifest interception point; on the native spawn path there is no manifest, so dial-presence is **could-not-check** (not clean) — detective at best, the preventive gate a target contingent on the outer-harness hook (dispatch interception model). The *appropriateness* of a specified value (over-/under-provisioned) is an AI-Engineer judgment, surfaced as an **advisory** through the viewers (REQ-14, per Q3) — never a fail-closed gate. *Grade (current → target):* convention/hand-audit → fail-closed / preventive-terminate at the manifest preflight for presence; detection/advisory for appropriateness. *Falsifier:* a dispatch manifest with defaulted/unrecorded dials (presence); an advisory right-sizing figure without provenance (appropriateness, REQ-14). *Bypass closed:* silent inherit (AIE mode: "model-tier choice made by intuition not per-task cost-benefit"); a native spawn with no manifest reported clean instead of could-not-check.
- **REQ-8 — Reads offset/limit-scoped.** A `limit=none` Read of a large governed file is flagged; the warm slice (REQ-6) removes the reason to full-load. *Grade:* detection. *Falsifier:* full-doc load where a slice was available. *Bypass closed:* full-load with no penalty. (The #821 lens that read the contract in 1–4-line windows is the positive control.)
- **REQ-9 — Composition→verifier binding.** The composition function (Slice 2) **computes** the SHOULD (required primer/domains/supplements for the phase/surface); the verifier reads the WAS from the synced run transcript (REQ-10) and **recomputes the SHOULD itself — it never reads an agent-declared composition as the SHOULD** (REQ-10, claim-not-oracle); conformance is `WAS ⊇ SHOULD`; the gate blocks the delta. The SHOULD is computed **role-scoped per REQ-18** — for a **review composition**, `SHOULD ⊇ process-governing set ∪ axis-activated product domains`; for a **build dispatch**, `SHOULD =` the phase composition matrix's primer + composed domains — plus, in both roles, the runtime/project always-on supplements (REQ-4). **The role (review vs build) is derived from the non-forgeable REQ-1 recorded phase** — Phase-3 → review composition; the build phases → build dispatch — **never from an agent-declared role field** (RT + QE converged): an agent-supplied role could self-shrink the SHOULD to the thinner build set, whereas the recorded phase cannot be forged (REQ-1/REQ-10). The process-governing set is not adopter-optional for reviews. *Grade:* CI-backed block. *Falsifier:* a conformant-marked run whose WAS is missing a SHOULD member; a **review** composition's computed SHOULD that omits a process-governing-set domain; a SHOULD taken from a declared composition rather than recomputed; a SHOULD whose **role input was taken from an agent-declared field** rather than derived from the REQ-1 recorded phase (a Phase-3 run self-labeled "build" to earn a thinner SHOULD). *Bypass closed:* declare a composition and dispatch a different (thinner) one; drop a process-governing domain to shrink a review's SHOULD so a thin WAS trivially satisfies it.
- **REQ-10 — The oracle is the server-synced, tamper-evident transcript copy — and nothing else.** The conformance oracle is **only** the run transcript as **synced to the crosslink server and made tamper-evident by corroboration** (§264/#815 keystone). The **local** `agent-<id>.jsonl` on the worktree disk is **agent-writable** (an in-harness agent has Bash + Write and can edit its own transcript file), so it is **not authoritative**: the verifier **REJECTS a local or un-synced transcript** as an oracle and reports **could-not-check** (never clean) when only the un-synced copy is available. The **sync channel** — crosslink-server transcript sync with corroboration tamper-evidence — is named here as an **upstream crosslink dependency** (a capability not yet present/wired; until it lands the oracle is unavailable and every conformance verdict resting on it is could-not-check, not clean). Evidence discipline: **`WAS` = the harness transcript's tool-use events *only*** (Reads, `tool_use`, `usage` — the events the agent cannot forge on the synced copy); **`SHOULD` = recomputed by the verifier from the composition function** (REQ-9), never taken from any agent-authored declaration; **the per-run composition declaration is a *claim to verify*, never the oracle** — the verifier recomputes SHOULD and compares it to the synced WAS, and never trusts a declared composition as evidence. *Grade (current → target):* could-not-check now (sync channel unbuilt) → independent-oracle (the only tamper-proof grade) once the server-sync dependency lands. *Falsifier:* a control resting on an agent-writable record; a verdict marked clean over a local/un-synced transcript; a SHOULD taken from an agent-authored declaration rather than recomputed. *Bypass closed:* the agent fabricates its own conformance evidence by editing its local transcript, or declares a composition the verifier then trusts instead of recomputing.
- **REQ-11 — Cost re-scoped to static price + records-based insight.** Retain the static price (Slice 2: the priced bill at build + CI bloat-gate) and answer the cost questions from the run records (per REQ-14). Retire the telemetry apparatus (OTel collector, dashboards, dollar ledger, calibration-tied-to-dollar-actuals) — under subscription auth, dollars are a projection; the binding constraints are usage windows and operator time (§144). *Grade:* spec-amendment (SO). *Falsifier:* a cost figure without capture-source provenance (§151, retained); a composition whose static price cannot be produced.
- **REQ-12 — Personas and supplements are controls, not prose.** Their enforceable content becomes conformance checks; their required content is delivered by injection (REQ-2/3/4); only irreducible judgment-shaped guidance remains as prose, and it is injected (not description-matched) and audited by the cold review that receives the same slice — the one instrument that catches read-but-ignored (§133). *Grade:* mixed (checks CI-backed; injection by-construction). *Falsifier:* a persona/supplement relied on solely as prose-to-be-read. *Bypass closed:* ship a discipline as a persona sentence and assume compliance (the founding failure).
- **REQ-13 — Review is independent-of-frame always; cold-vs-warm on artifacts is a right-sized dial.** Adversarial review is by a different agent, never given the author's reasoning (independence). Reviewers may be **warm on raw artifacts** (handed the raw diff/design/contract slice) but never on a curated summary (curation re-imports the author's blind spot). True cold (re-load raw yourself) is reserved for terminal rounds guarding collective anchoring. *Grade:* discipline mechanized as a dispatch-composition rule. *Falsifier:* a reviewer handed the author's rationale, or a curated summary in place of the raw artifact. *Bypass closed:* "cold" used to justify redundant re-load without adding independence (the cross-agent waste of REQ-6).
- **REQ-14 — Efficiency insight engine.** A reader over the run records surfaces the AI-Engineer dimensions with provenance on every figure (**recorded / measured / judgment / could-not-check**): capture-source provenance; cost-band cataloging per operation; prompt-cache discipline (5m vs 1h TTL utilization); sub-agent scope-down (warm vs cold); model-tier + effort right-sizing per task; cross-agent redundant-load; **per-entry wall-clock duration** (`durationMs`, a recorded transcript field); **read-inflation modeled as compounding re-inclusion of context bytes across turns *net of the `cache_read` discount*** — not a per-read boolean flag: a full-load is costly only to the extent it lands as `cache_creation`, and re-inclusion is cheap once warm, so the metric is the fresh-load byte delta, not a count of Reads. The fourth provenance value, **could-not-check**, tags a figure whose source record is **unavailable** (an un-synced transcript, REQ-10; a native spawn with no manifest, REQ-7; the §144 **usage-window / rate-limit-window** figures — the declared binding constraints — which are **not in the run transcript**) — reported honestly, never silently dropped nor shown as a real metric. *Grade:* detection/advisory, surfaced through crosslink's existing viewers (§149 "vsdd builds no viewer"). *Falsifier:* an advisory figure without one of the four provenance tags; a calibration claim with no linked actual; a could-not-check figure presented as recorded/measured.
- **REQ-15 — The design process is itself conformance-checked and Red-Teamed** (operator ruling 2026-07-31). A design/review cycle's own dispatches (including reviews) are subject to REQ-1..10 and REQ-16, and Red Team reviews both the process (was the correct path the only path, or was an easier bypass available and taken) and the artifact (are the controls circumventable). *Grade:* CI-backed (the cycle's own dispatch records are checked) + adversarial review. *Falsifier:* a cycle that declares a composition but whose dispatch records show the personas unloaded (this cycle's own opening — the paraphrase bypass, caught by the operator; and the authoring's Read-not-invoke of the domains — both are findings that the control must be mechanized, not human-caught).
- **REQ-16 — Skill invocation is the audited activation signal** (operator ruling 2026-07-31). The composition's required **skill-delivered** governing context — the **primer and the composed domains** — is delivered and audited as **skill invocations** (`/design`, `/vsdd-phase-<n>`, the composed `/vsdd-domain-*`) — the record of *which skills the agent invoked* is the unambiguous activation signal, checked against the composition's required set. **Supplements are carved out of the invocation audit (QE):** supplements (`claude-code-cli`, `bash`, `rust`, task-surface supplements) are delivered by **injection, not invocation** — they emit **no `attributionSkill` event** — so their activation signal is **injection-presence per REQ-4**, not a skill-invocation event. Auditing a supplement as a *missing invocation* is **mirror-vacuity** — the supplement leg could never pass on a conformant run — so primers/domains stay on the invocation signal and supplements stay on the REQ-4 injection-presence signal. *Capture-source (C8):* the invoked-skill signal is recorded in the transcript as **`attributionSkill`** on the invocation events — this is the field the post-dispatch audit reads for primers/domains; a bare `Read` event carries only a `file_path` (the weaker signal), never an invocation. *Grade:* CI-backed audit of recorded skill invocations. Ranking of activation strength: **skill invocation (audited activation) > recorded Read (weaker: content loaded, may be skimmed) > paraphrase-in-prompt (nonconformance)**. *Falsifier:* a run under a declared composition whose skill-invocation record omits a required skill (even if the file was Read); a dispatch relying on paraphrase. *Bypass closed:* Read-instead-of-invoke (the weaker signal — flagged, not passed); paraphrase (nonconformance). This is the single clearest "is the harness cargo-cult" probe: the invocation record either shows the disciplines fired or it doesn't. **Two fail-loud checkpoints (operator ruling 2026-07-31):** (a) *preflight* — a dispatch whose composition is not injected terminates before it runs (REQ-2/3/4); (b) *post-dispatch* — the skill-invocation record is audited after the run against the composition's required set, and **fails loud** if a required **primer or domain** skill was not *invoked* (injection-present ≠ invoked-and-used; this closes the injected-but-ignored hole); **supplements are audited on injection-presence (REQ-4), not invocation**. *Grade:* preventive-terminate + post-dispatch fail-loud CI audit. (Skills are named an under-invoked mechanism in the REQ-20 underutilization audit.)

- **REQ-17 — Phase agent-work is dispatched + audited, never done in the orchestrator session** (operator ruling 2026-07-31; keystone; supersedes the "design is attended, execution is autonomous" split of the 2026-07-20 ruling). The operator/orchestrator session is not a dispatched agent, so nothing it does is conformance-audited — making in-session phase-work the ultimate bypass (the orchestrator does the most work, unchecked). Therefore the **agent-work of every phase — design authoring AND implementation — runs as a dispatched, conformance-audited agent** (subject to REQ-1..16), exactly like reviews. The operator session's only legitimate work is the human's irreducible slots (§161: oracle authorship, triage, ratification, consent grant, spec-intent) plus orchestration (dispatch + audit); its own control is REQ-19. Re-scoped split: **human-judgment attended; all phase agent-work dispatched + audited.** *Grade:* CI-backed (a phase artifact whose authoring/implementation has no conformance-audited dispatch record is flagged) + the same preflight/post-dispatch fail-loud checkpoints. *Falsifier:* a phase artifact (design doc, code) produced with no dispatched, conformance-audited agent record behind it — i.e., done in-session. *Bypass closed:* the orchestrator quietly does the phase-work itself (the whole of this session, and the authoring of this very doc — the live evidence). *Bootstrap interim (marked):* until this subsystem, the crosslink injection point, and a working kickoff (#837) land, phase agent-work is done in-session and **hand-audited** (personas hand-loaded, invocations noted) — a format-carried interim explicitly recorded as such at each dispatch, never the target; this doc's own authoring is a marked instance. **These bootstrap hand-audits are themselves could-not-check-grade (Security S-N4):** they are **greps over the local, agent-writable transcripts**, not verdicts from the independent server-synced oracle (REQ-10) — so "verified from transcript" during bootstrap is **could-not-check-grade corroboration, never the independent-oracle grade**; the honesty bar applies to the amendment's own audit trail.

- **REQ-18 — Adopter-inheritance: the process-governing set (for reviews) ∪ axis-activated product domains** (operator ruling 2026-07-31, contract re-scope in Part 3). The composable domain roster partitions **totally** into three disjoint classes (naming fixed — "baseline" was overloaded; the two sets are now named distinctly):
  - **Core always-on quartet** — **Solution Owner, Solution Architect, Software Engineer, Quality Engineer** — every adopter, every phase.
  - **Process-governing set** — the quartet **plus AI Engineer, Platform Engineer, Red Team, Security, Data Engineer, Documentation Reviewer, Technical Writer** — inherited by *every* vsdd adopter for the harness to **function**, because the process **dispatches AI** (AIE), **enforces via CI/hooks** (PE), **is circumventable + oracle-trust-dependent** (RT + Security), **runs on mdatron schema-data** (DE — the registry + the exercise-registry), and **produces governed prose** (DR + TW).
  - **Product-reviewing / axis-activated** — **UX, Accessibility, Privacy, Localization**, and **Performance Engineer (code-shipping-activated** — active when the adopter ships code / declares a performance axis, per the phase-1a primer's "PE + PerfE if the project ships code"), plus **product activation** of RT / DR / AIE — activate per the adopter's declared axes.

  **Meta-domains — Sanity Check and VSDD-Methodology — are phase-level validators, NOT partition members** (they rubber-duck / last-resort-validate at the phase level and are never composed into a dispatch's domain set), which is what makes the three classes above a **total** partition of the composable roster.

  **Audit level (operator decision — the review-roster level):** the **process-governing set** is the required roster for **review compositions** (the cold-review fan-out that governs a cycle). A **build-phase dispatch is NOT required to load the full set** — it carries only its **phase-appropriate primer + the phase composition matrix's composed domains + supplements**. This resolves the efficiency ⇄ cold-review-independence contradiction: forcing every build dispatch to load all eleven would both bloat every build and dilute the reviewer-independence the roster exists to provide. The required set is therefore **role-scoped**: for a review composition, `SHOULD ⊇ process-governing set (∪ axis-activated product domains)`; for a build dispatch, `SHOULD =` the phase-matrix output (∪ the runtime/project always-on supplements, REQ-4). **The role selector is the non-forgeable REQ-1 recorded phase** (Phase-3 → review; the build phases → build), **not an agent-declared field** (RT + QE) — so a review cannot be self-relabeled as a build to earn the thinner build SHOULD (the recorded phase cannot be forged, REQ-1/REQ-10). *Mechanism:* the composition function computes the role-scoped partition; REQ-9's gate enforces it. *Grade:* CI-backed block (via REQ-9). *Falsifier:* a **review** composition whose computed SHOULD omits a process-governing-set domain; a WAS marked conformant while missing a required-for-its-role domain; a composable domain left unplaced by the partition. *Bypass closed:* an adopter (or this project) silently drops a process-governing domain from a **review** (e.g. runs the cold review without Red Team or Security), yielding a thinner SHOULD that a thin review trivially passes — the process-governing set is inherited to function for reviews, not opt-in. (Conversely, loading the full roster onto every build dispatch is *not* the conformance bar.)

- **REQ-19 — Operator-session control (not a dispatched agent, still audited)** (operator ruling 2026-07-31). The operator/orchestrator session is not a dispatched agent, so nothing it does passes through per-agent conformance audit — the REQ-17 concern at the session level (the session that does the orchestration is otherwise the one unchecked actor). Its control is the **session-start hook** — which injects the session skill + the runtime-determined always-on supplements (`claude-code-cli`, `bash`) + the phase pointer — plus the **read-gate** on governed acts. Per REQ-17 (phases-dispatched) the operator session loads **less**: orchestration + the human's irreducible §161 slots (oracle authorship, triage, ratification, consent, spec-intent); heavy phase context goes to the dispatched agents. It is **not exempt** from the exercise-audit: **session-start-hook-fired** + **session-skill-invoked** are audited and **fail loud**. *Mechanism:* session-start hook (by-construction injection) + read-gate; exercise-audit over the hook/skill trace. *Oracle boundary (REQ-10):* the session-start-hook / session-skill trace is authoritative only as the **server-synced, tamper-evident copy** — a **local, un-synced trace is agent-writable → could-not-check** (like every REQ-10 record), never clean; the exercise-audit's verdict is independent-oracle-grade only over the synced copy. *Grade:* by-construction (hook fires) + CI-backed fail-loud audit. *Falsifier:* an operator session with no session-start-hook trace, or with the session skill never invoked; an exercise-audit verdict marked clean over a local/un-synced trace. *Bypass closed:* run the operator session bare (no hook, no session skill) so the highest-work, otherwise-unaudited session escapes conformance entirely.

- **REQ-20 — Mechanism-per-control + underutilization audit** (operator ruling 2026-07-31). Every control/surface **names its correct agent-first mechanism** — MCP tool · hook · skill · crosslink affordance · CI leg · sentinel — and rides it; hand-rolling a feature that already exists is **both** §130 nonconformance **and** underutilization (an authored/available affordance left on the table). The **underutilization audit is a first-class design output** of this subsystem, naming for each authored/available mechanism its build/use status and its correct home: the **knowledge-surfacing need** rides existing affordances (§355 leverage-not-build): **crosslink knowledge** (the `search_knowledge` MCP + knowledge pages) for methodology/shared knowledge, the **injected/composed methodology corpus** (skills) at action time, the agent's built-in **WebFetch / WebSearch** for external docs, and **each sibling tool's own docs surface** (mdatron, crosslink) — grepping files for this knowledge is the hand-roll anti-pattern (REQ-5/§130), and a `vsdd mcp-serve` docs-server is **CUT (superseded)** as redundant with those affordances, so it is *not* an unbuilt-underutilization item; **Cron / PushNotification / RemoteTrigger** (scheduled sweeps + budget / rate-limit alerts — unused); **Skills** (under-invoked — Read-instead-of-invoke, REQ-16); crosslink **SWARM** (bypassed for the `Workflow` tool — the leverage-vs-build point); **SENTINEL** (the §149 home for scheduled efficiency-advisory sweeps — unused); crosslink **VIEWERS / mission-control** (§149 "vsdd builds no viewer" — the surfacing home for the efficiency insights); crosslink **INTERVENE** (mid-flow records); the **milestone mechanism** (mandated — layers/slices as crosslink milestones — and machinery-backed by the active-milestone gauge + the phase-pointer-against-milestone-state check, yet the contract's own mid-cycle-without-milestones detector is designed-but-unbuilt and no enforcement point creates or requires a milestone: the pre-code guard forces an issue, never a milestone; fix: build the mid-cycle-without-milestones detection + an active-milestone enforcement point); the **tracker, consulted-before-create** (populated yet agent-unconsulted before a new create — a duplicate opened past an existing correctly-scoped issue because the only enforcement point that fired forces create-before-code, never search-first; fix: a find-or-create enforcement point that surfaces the existing issue before a new one opens). *Mechanism:* act-to-affordance map (§130) mechanized as detection + the underutilization audit as a design output. *Grade:* CI-backed detection (hand-rolled-existing-feature flagged) + advisory (unbuilt/unused correct mechanism named). *Falsifier:* a control that hand-rolls a mapped/available affordance with no stated reason; a named correct mechanism left unbuilt/unused where it is the right home; a mandated-and-machinery-backed mechanism (the milestone) whose own designed detector is left unbuilt with no enforcement point requiring it; a populated mechanism (the tracker) left unconsulted before a create because no search-first / find-or-create enforcement point exists. *Bypass closed:* reach for shell/grep/hand-roll to skip an affordance and its checks (the REQ-5 bypass generalized to every mechanism); leave the correct mechanism unbuilt and quietly substitute a weaker manual path — the correct mechanism must be the path of least resistance (RT: correct path = only path).

- **REQ-21 — Dispatch spend-shape bound: three distinct legs, honestly graded** (folds #831 — the mdatron#11 escape). Binding the dispatch's spend shape (fan-out topology + a hard agent-count ceiling) is **three separate controls at three grades**; conflating them as one "fail-closed gate" was the error — **post-hoc records cannot prevent a spend**:
  1. **Ratification-time declaration-completeness (block-grade — genuinely enforceable).** The composition, at ratification, **must declare a bounded fan-out shape + an agent-count ceiling**; a ratified composition that binds the lens/domain set (REQ-9) but **omits the fan-out shape or the ceiling fails the gate (fail-closed)**. This blocks because it reads a *document* at gate time — it guarantees the ceiling *exists*, and prevents nothing about runtime spend beyond that.
  2. **Runtime admission-control (the only leg that PREVENTS the spend — UNBUILT/advisory).** The only mechanism that actually stops the spend is a **spawn interceptor that refuses agent N+1** once the declared ceiling is reached. This needs the **outer-harness `PreToolUse` deny hook on `Task`/`Agent`** (dispatch interception model) and **does not exist today**; until it is built it is **advisory, not enforcement (marked UNBUILT)**. Naming it as the preventive leg — rather than pretending the gate or the records prevent the spend — is the honesty bar.
  3. **Records-based detection (post-hoc — ADVISORY only).** Per-agent / per-phase running usage from the transcript `usage` records (the efficiency engine, REQ-14 — records-based, no new telemetry) **flags** a fan-out that breached (or is trending toward) the ceiling. Because it reads records *after* the tokens are spent, it is **detection/advisory — never fail-closed** (it surfaces the overspend; it cannot undo it).

  The **refutation mechanism** is specified gate-checkably at leg 1 — a finding is "hallucinated" iff it **does not resurface across rounds** — so a synchronous per-finding verifier fan-out cannot be silently substituted for it. *Grade (per leg):* (1) CI-backed block / fail-closed at the ratification gate; (2) preventive **only once the outer-harness spawn interceptor is built** — advisory/UNBUILT now; (3) detection/advisory (REQ-14). *Falsifier:* a ratified composition that binds the lens set but omits the fan-out shape/ceiling (leg 1); a records-based flag or a not-yet-built interceptor **labeled fail-closed** (legs 2/3 — reconciles with REQ-22's detection-only-is-not-governance bar); a refutation implemented as a synchronous per-finding fan-out instead of across-round non-resurfacing. *Bypass closed:* keep the declared composition faithful while opening an **undeclared, uncapped verifier-per-finding fan-out** (mdatron#11: a phase-3 roast sprawled to 39 agents / 2.27M tokens because the gate had ratified the lenses, not the run's shape); or claim the spend is *prevented* when only detection exists. Extends REQ-9, REQ-6, REQ-14, and the Red-Team circumvention lens (REQ-15).

- **REQ-22 — A sustained escape corpus is the Red-Team coverage bar** (folds #817 — the wider evaluation of the built system). The design/review cycle maintains an **escape corpus** — the enumerated escape paths that agents (this project's own cycles included) have taken against the *implemented* system — and Red-Team coverage is audited against it: for each escape class the cycle names **the control, its non-forgeable (corroborated) trace, and whether the control shifts the incentive gradient (compiler-shaped forcing feedback) or only detects**. The **detection-only-is-not-governance** honesty bar holds: an advisory-only control in the bootstrap window is marked advisory, never called enforcement; and a check whose input is unavailable reports a distinct **could-not-check** (checks-run-clean ≠ checks-dormant), never a false clean. An escape with no named non-forgeable trace or no gradient-shift is **not covered**. The corpus is a living artifact the cycle must sustain — a probe-found escape is added as it is found — extending REQ-15's process-is-checked framing and feeding the audit surface (the governing law). *Grade:* adversarial review (Red Team) + CI-backed where the escape's control is mechanized. *Falsifier:* an escape class with no mapped control / non-forgeable trace / enforcement-vs-advisory mark; a control mislabeled enforcement that only detects in the bootstrap window; a dormant check reported as clean; a probe-found escape never added to the corpus. *Bypass closed:* declare adversarial coverage while the real escape paths against the built system — forgeable gate-evidence (the phase-advance-on-a-fabricated-gate-record cheat), dormant-reported-as-clean false assurance, visible-prose instruction injection, and the composition-gate fan-out — go unmapped and unmarked (the #817 escapes; the #818 built-layer fixes are their enforcement legs).

- **REQ-23 — Secret redaction is a three-leg ladder, each honestly build-graded** (Security cluster's redaction half; supplies the half the oracle fix left open — REQ-10's hardening routes raw tool-inputs to the server, so redaction must move to the boundary vsdd/CI control, off the agent-writable local copy). The run transcript records tool inputs — Bash commands, file contents, `Read` `file_path`, `tool_use` inputs — a **credential-carrying surface beyond config/committed files**. Redaction is **three separate controls, at three grades, against three distinct threats**; conflating them (or placing all of it "before recording" on the local copy, as the current anonymization prose does) is the error:
  1. **Accidental leakage in COMMITTED text** (governed corpus / code / docs) → the **`check-anonymization` pre-commit hook** applying the anonymization patterns (`templates/registry/anonymization-patterns.yaml`, deployed by `vsdd init`). This is the **correct mechanism**, but it is **authored-not-exercised today** (record-verified this cycle): the **patterns ship, but no hook reads them** — `.claude/hooks/` carries no `check-anonymization` hook. It therefore lands as an **exercise-registry entry that fails loud** (patterns present + hook never fires = authored-but-never-exercised, the governing law). *Threat stopped:* a maintainer/agent **accidentally committing** an API-key-shaped string into a governed file. *Grade (current → target):* authored-not-exercised (convention) → CI-backed block (pre-commit hook wired to the patterns).
  2. **Accidental leakage in the TRANSCRIPT / run-record** (not git-tracked, so **unreachable by the pre-commit hook**) → **sync-side redaction on the crosslink sync channel**, applied **server/CI-side before the corroboration copy is formed** — the boundary **vsdd/CI controls, not the agent-writable local copy** (REQ-10). *Ordering vs tamper-evidence:* redaction is **part of forming the corroborated copy**, so it (a) does **not** run agent-side and (b) does **not** break the corroboration hash — the hash is computed over the already-redacted synced copy, not the raw local one. This is an **unbuilt upstream dependency** (rides the same server-sync + corroboration channel REQ-10 names as unbuilt). *Threat stopped:* a secret **accidentally** captured in a tool-input surface that never touches a committed file. *Grade (current → target):* could-not-check now (sync channel unbuilt) → server/CI-side block once the sync + corroboration channel lands.
  3. **DELIBERATE exfiltration by the untrusted agent** → **capability-restriction** — scope secrets **out of the agent's context / env** so there is nothing to leak — **NOT pattern-redaction**, which is **theater against a deliberate actor** who can encode / split / transform a secret to defeat any pattern. *Threat stopped:* the untrusted checked agent **intentionally** exfiltrating a credential it can read. *Grade (current → target):* the **top ladder rung — harness-level capability restriction** (the outer harness the agent cannot reach: secrets never enter its context/env), an outer-harness dependency, not a vsdd-layer control.

  **Threat-model summary:** leg 1 stops *accidental commit* leakage; leg 2 stops *accidental transcript* leakage; leg 3 stops *deliberate* exfiltration — and **only leg 3's capability-restriction is credible against a deliberate actor** (legs 1/2 are accidental-leakage controls, never anti-exfiltration). *Mechanism:* pre-commit hook (leg 1) · sync-side boundary redaction (leg 2, upstream dependency) · capability-restriction / secret-scoping (leg 3, outer-harness dependency). *Falsifier:* a redaction control present **only as prose/data with no firing hook** (leg 1's current state — patterns without a reader — flagged authored-but-never-exercised); redaction placed **agent-side / before the local record** (rejected by REQ-10 — the agent-writable copy is not the boundary); **pattern-redaction claimed as the defense against deliberate exfiltration** (theater — it must be capability-restriction). *Bypass closed:* ship the anonymization patterns as data nobody reads and call the transcript "redacted"; redact on the agent-writable local copy and call it tamper-evident; rely on patterns against an agent that deliberately transforms the secret.

## Architecture

**Leverage crosslink; supply only the vsdd layer** (§355: crosslink's dispatch primitive "is strong on crosslink protocol and carries none of the vsdd layer"). 
- **Leverage (do not rebuild):** `swarm`/`kickoff` dispatch, worktrees, sessions (phase pointer in breadcrumbs §37), trust/signing, preflight (§108), the viewers — mission control / tui / web dashboard (§149, "vsdd builds no viewer"; the efficiency insights surface there), **crosslink knowledge** (`search_knowledge` MCP + knowledge pages) plus the agent's built-in **WebFetch / WebSearch** and each **sibling tool's own docs surface** (mdatron, crosslink) for the knowledge-surfacing need (a `vsdd mcp-serve` docs-server is **cut (superseded)** as redundant with these — neither leveraged nor built), sentinel (the scheduled-sweep home, §149), and intervene (mid-flow records). The **server-synced, tamper-evident** Claude Code transcript is the conformance oracle (REQ-10) regardless of orchestrator; a local/un-synced transcript is agent-writable and is **not** authoritative (could-not-check). Mechanisms currently left on the table are named in the REQ-20 underutilization audit.
- **Build/supply (the vsdd layer crosslink deliberately doesn't carry):** the **composition function** (Slice 2 — the SHOULD, computed **role-scoped** per REQ-18: for reviews the process-governing set ∪ axis-activated product domains, for build dispatches the phase-matrix output, plus the runtime/project always-on supplements per REQ-4); the **injection point** into the dispatch prompt — **vsdd-owned** (vsdd assembles the prompt from the composition and rides crosslink's dispatch primitive, §355) until crosslink absorbs it via a generic injection hook in kickoff prompt-assembly (the §81 injection seam, filed as a crosslink feature request); the **conformance verifier** as a **Slice-4 gate leg** (`vsdd gate conformance`) that reads the synced-transcript WAS (REQ-10), **recomputes** the SHOULD, compares, and gates; the same gate **binds the dispatch fan-out declaration + a hard agent-count ceiling at ratification** (REQ-21 leg 1, block-grade), while runtime *prevention* of the spend needs the **unbuilt outer-harness spawn interceptor** (REQ-21 leg 2) and the records-based usage flag is **post-hoc advisory** (REQ-21 leg 3 / REQ-14 — no new telemetry apparatus); the **efficiency insight engine** as a **sibling command** (reader over records, provenance-tagged). Verifier + engine home in `vsdd-core` (pure over the records) with a `vsdd`-binary command surface; they consume the same run records analyzed by hand this session — the **run transcripts** (`agent-<id>.jsonl` usage/tool events); the lifecycle index `journal.jsonl` is a **distinct**, harness-produced file (agent-cannot-author) that is **not the oracle and not read as WAS / efficiency substrate** — the verifier + engine read only the run transcripts — per the record-capability knowledge page. The static-price half of Cost stays in Slice 2 (REQ-11).
- **The oracle + trust boundary (SA/RT):** the checked agent is untrusted with respect to its own conformance; evidence comes **only** from the **server-synced, corroboration-tamper-evident** transcript (REQ-10) + CI over that synced state (§264/#815). The **local `agent-<id>.jsonl` is agent-writable** (Bash + Write) and is **rejected** as an oracle — an un-synced transcript yields **could-not-check, never clean**; the server-sync channel is an **upstream crosslink dependency** (not yet wired). This is the hard-to-undo trust-boundary placement — the verifier must never read an agent-writable record, nor an agent-declared composition (REQ-9), as authoritative.
- **The escape corpus (RT):** the enumerated escape paths agents have taken against the *implemented* system are a sustained artifact (REQ-22); Red-Team coverage is audited against it, each escape carrying its control, its non-forgeable (corroborated) trace, and an enforcement-vs-advisory mark (the detection-only-is-not-governance honesty bar).
- **Delivery of injection while the upstream capability is unbuilt:** during bootstrap, injection is format-carried (the dispatch prompt assembles the required primer/domains/supplements from the composition) with the recorded Reads as the interim verification, until crosslink's kickoff prompt-assembly ships the §81 injection seam (#837); the skill-invocation audit (REQ-16) becomes the activation signal once it lands.

## Design decisions (resolved)

### Q1 — Verifier home: RESOLVED (option a)
The conformance verifier is a **Slice-4 gate leg** (`vsdd gate conformance`) that consumes the composition function's SHOULD (Slice 2) and reads the transcript WAS. The **efficiency insight engine is a sibling command** — a reader over the run records — homed alongside the verifier in `vsdd-core` (pure over the records) with a `vsdd`-binary surface. Retiring the telemetry/cost apparatus (REQ-11) leaves the engine this clear home; the **static-price half stays in Slice 2**.

### Q2 — Injection-point delivery: RESOLVED (option a)
**vsdd assembles the dispatch prompt itself** (composition → prompt) and rides crosslink's dispatch primitive, treating the injection point as **vsdd-owned until crosslink absorbs it** (§355's "vsdd injecting … into the dispatch vehicle's prompt"). A crosslink **feature request** is filed for a generic injection hook in kickoff prompt-assembly (the §81 injection seam); the #837 kickoff bugs are tracked separately (operator-owned). **Recorded-Read verification holds during bootstrap**; the skill-invocation audit (REQ-16) becomes the activation signal once the injection point lands.

### Q3 — Right-sizing advisory or gate: RESOLVED (advisory for mis-sized; terminate for missing)
The **presence/specification** of the model + effort dials is a **hard gate**: unspecified dials fail closed and terminate at preflight (REQ-7). The **appropriateness of the value** (over-/under-provisioned) is an **AI-Engineer judgment → advisory only**, surfaced through the viewers (REQ-14). Judgment cannot fail-closed cleanly; only the missing-dial case blocks.
