# Feature: Verifiable-conformance + efficiency subsystem

## Summary
The meta-harness must **prove, from the run record, that its own disciplines fired for every dispatched agent** — the phase-appropriate primer, composed domains, and supplements were loaded; the intended tools were used; the run was right-sized (cache, model/effort, targeted reads). "Availability is not activation" (contract §133) is already ratified law; this subsystem **mechanizes** it, turning cargo-cult performance (personas that ship as files nobody loads) into verified conformance. **Verifiable conformance is the center of gravity; efficiency/right-sizing is one axis under it** (operator ruling 2026-07-31). This is a spec amendment: it supersedes `DESIGN-OBSERVABILITY.md`, re-scopes "Cost is knowable" (§140-153), and re-grounds the AI-Engineer domain from observability-lens to measured right-sizing/conformance judge; Red Team is re-pointed at control circumvention.

**Founding evidence (two live instances, not hypothetical):** (1) the #821 cold-review lenses read no `vsdd-domain-*` persona — they got their lens from the dispatch prompt, not the files (recorded in `wf_0ac03bda-2ee` transcripts). (2) *This cycle's own opening* bypassed the personas — the orchestrator dispatched a general-purpose subagent with a paraphrase of the composition until the operator caught it; the correct path (load the files) was not the only path, and the catch was **human, not mechanized.**

## Amendment scope (this doc is the amendment manifest)
This spec amendment has **three parts**; only Part 1 is authored in this document.

1. **This subsystem design** — the conformance + efficiency subsystem (this document): the governing law, the exercise-registry abstraction, the composition→verifier loop, and the currently-uncovered controls.
2. **Governed-corpus edits** — the ~11 domain-persona edits (telemetry purge + re-ground/re-point + extensions, per the #840 domain-edit-scope comment 2026-07-31), the primer pass (the phases-dispatched keystone, the composed-context-loaded conformance discipline, the composition-SHOULD, and the composition-declaration template), and the supplement-activation edits (the runtime-determined always-on tier, REQ-4). **Dispatched + cold-reviewed separately; referenced here, not authored here.**
3. **Three contract re-scopes** — "Cost is knowable" §140-153 (static price + records-insight; retire the telemetry apparatus, REQ-11); the attended/autonomous split (superseded by REQ-17); the adopter-inheritance model (REQ-18). **Dispatched + cold-reviewed separately; referenced here, not authored here.**

Parts 2 and 3 re-enter phase 1a/1b under their owning domains with cold review; the operator (SO) ratifies at the exit gate. This doc does not hand-edit personas, primers, supplements, or the contract.

## Requirements

**The governing law (operator ruling 2026-07-31): *authored is not exercised* — the sibling of "availability is not activation" (§133).** §131's installed-artifact manifest proves a mechanism is *installed*; this subsystem proves it *fired*. Every control the methodology authors must emit a provable "it ran" trace, audited against a **registry of authored controls + their expected-fire proof** (the exercise-layer twin of the installed-artifact manifest; a control lands in the tree paired with its fire-check, the same discipline as "artifact + manifest entry land together"), and **fails loud on authored-but-never-exercised.** REQ-1..20 below are instances of this law; the audit surface it governs (mechanism → proof-it-fired → fail-loud condition → home): **skill** → invocation record (REQ-16, this subsystem); **hook** → hook-trace vs git history (§133/§136); **CI check / required gate** → the check *ran*, not merely passed (this subsystem; the mis-wired-required-check case); **tool/affordance** → tool-call vs hand-roll (REQ-5/§130); **schema/validator** → validated non-vacuously (generalize the #825 canary); **composition** → computed not echoed (Slice 2/REQ-9); **preflight** → record precedes dispatch (§116); **dispatch manifest** → recorded + round-parity (Slice 6); **red-gate/pins** → executed-pin (Slice 4); **routing** → filed routing (Slice 1, live); **read-gate** → Reads precede the edit (§133); **dials** → recorded (REQ-7); **signing** → signed where configured (§116); **session-start (operator session)** → session-start-hook-fired + session-skill-invoked (REQ-19, this subsystem). Scope discipline (SO): the built/other-slice rows are *referenced*, not re-owned; this subsystem newly contributes the abstraction (the law + the exercise-registry) and the uncovered cases (skill-invocation, dispatch conformance, composition-computed, CI-ran-not-just-passed, operator-session, mechanism-per-control). The canonical mechanism → proof → fail-loud → home table is preserved durably in the `run-record-capability-and-audit-surface` knowledge page.

Each conformance invariant is a **control**, stated as: mechanism · enforcement-ladder grade · falsifier · the Red-Team bypass it closes. Prose is convention grade (the bottom rung, the vibes that cargo-culted) and is never the delivery form.

- **REQ-1 — Phase is recorded.** Every dispatched agent's run carries the phase it executes, sourced from the state artifact / crosslink session breadcrumb (§37), not self-asserted. *Grade:* recorded (verification-only). *Falsifier:* a dispatch whose record names no phase, or a phase disagreeing with the milestone state. *Bypass closed:* run "phaseless" and claim any discipline post-hoc.
- **REQ-2 — Phase primer loaded (missing → terminate).** The phase primer for the recorded phase is present in the dispatched agent's context **by injection at dispatch**, delivered by the golden-path dispatcher (`vsdd dispatch`, below). A dispatch whose composed context lacks the required primer **fails the dispatch preflight (§108, fail-closed) and is terminated before it runs**, with a message routing back to the golden path — not launched-then-flagged. Verified after by a Read/injection event for the primer in the transcript. *Grade:* preventive-terminate at preflight (the mis-invoked agent never proceeds) + CI-backed verification backstop. *Falsifier:* a run that executed without the required primer present. *Bypass closed:* inline the primer's content in the prompt (no Read recorded); read-then-ignore (residual → cold review, REQ-13); dispatch raw `kickoff` bypassing the composer (→ preflight terminates it).
- **REQ-3 — Composed domains loaded (missing → terminate).** The domain personas the composition function requires are present by injection; a dispatch missing any required domain **fails preflight and is terminated**; verified after `Reads ⊇ composition-required domains`. *Grade/falsifier/bypass* as REQ-2. *Bypass closed:* load fewer/wrong domains; paraphrase them in the prompt (the #821 + this-cycle failure — the exact live evidence).
- **REQ-4 — Supplements loaded (missing → terminate); three-tier activation.** The supplements in scope are present by injection; a dispatch missing an in-scope supplement **fails preflight and is terminated**; verified after. *Supplement activation model (governed-corpus edit in scope, Part 2):* three tiers — (1) **runtime-determined always-on** — `claude-code-cli` whenever runtime = Claude Code, and `bash` for **every** agent (the shell is load-bearing for all agents — 91 Bash calls in the #821 run prove it); (2) **project-determined always-on** — `rust` for this Rust project; (3) **task-determined** — per surface (`github-actions` / `json` / `markdown` / etc.). The composition SHOULD includes the runtime + project supplements **unconditionally**; task-determined supplements enter the SHOULD only when their surface is in scope. *Gap named:* current supplement frontmatter gates by `languages_or_interfaces` only — there is no runtime-determined-always-on tier — so adding that tier is a governed-corpus edit in this amendment. *Grade:* preventive-terminate at preflight + CI-backed verification. *Falsifier:* a dispatch missing a runtime/project always-on supplement (even with no task surface named), or missing an in-scope task supplement. *Bypass closed:* skip; wrong-language supplement; treat a runtime/project always-on supplement as task-gated and omit it.
- **REQ-2/3/4 golden path — `vsdd dispatch`.** The composer that assembles the composition (SHOULD) into the dispatch and injects it by construction is the **path of least resistance** — the easy, one-command way to dispatch — so agents naturally take it; a raw `crosslink kickoff` that skips it carries none of the vsdd layer and fails preflight (REQ-1..4/7). Correct path = only path.
- **REQ-5 — Intended tools used; no hand-rolled affordance.** A methodology act uses its mapped tool/affordance (act-to-affordance map §130); a Bash string re-implementing a mapped affordance is a flagged nonconformance. *Grade:* CI-backed detection. *Falsifier:* a hand-rolled equivalent of a mapped affordance with no stated reason (§130's own falsifier, now checked). *Bypass closed:* hand-roll the tool's job in shell to skip the tool and its checks — must also make the tool the path of least resistance (RT: correct path = only path). (Generalized to every mechanism in REQ-20.)
- **REQ-6 — Cache leveraged; warm handoff.** Shared context is passed to a dispatched agent as a warm slice, not cold-reloaded per agent; verified by `cache_creation` analysis (cross-agent redundant fresh-load of the same context is flagged). *Grade:* by-construction in the dispatch primitive + detection. *Falsifier:* N cold agents each `cache_creating` the same base context. *Bypass closed:* cold-reload anyway (AIE sycophancy mode: "sub-agent re-loads context the parent already has"; "prompt-cache hit assumed across 5-minute TTL boundary").
- **REQ-7 — Model + effort specified (presence is a hard gate; appropriateness is advisory).** Every dispatch records explicit model and effort dials; unspecified dials **fail closed at dispatch preflight** (§91 "never inherited") and terminate the dispatch. The *appropriateness* of a specified value (over-/under-provisioned) is an AI-Engineer judgment, surfaced as an **advisory** through the viewers (REQ-14, per Q3) — never a fail-closed gate. *Grade:* fail-closed / preventive-terminate at preflight for presence; detection/advisory for appropriateness. *Falsifier:* a dispatch with defaulted/unrecorded dials (presence); an advisory right-sizing figure without provenance (appropriateness, REQ-14). *Bypass closed:* silent inherit (AIE mode: "model-tier choice made by intuition not per-task cost-benefit").
- **REQ-8 — Reads offset/limit-scoped.** A `limit=none` Read of a large governed file is flagged; the warm slice (REQ-6) removes the reason to full-load. *Grade:* detection. *Falsifier:* full-doc load where a slice was available. *Bypass closed:* full-load with no penalty. (The #821 lens that read the contract in 1–4-line windows is the positive control.)
- **REQ-9 — Composition→verifier binding.** The composition function (Slice 2) computes the SHOULD (required primer/domains/supplements for the phase/surface); the verifier reads the WAS (the run record); conformance is `WAS ⊇ SHOULD`; the gate blocks the delta. The SHOULD is computed as **process-governing-baseline ∪ axis-activated-product-domains** (REQ-18) plus the runtime/project always-on supplements (REQ-4) — the baseline is not adopter-optional. *Grade:* CI-backed block. *Falsifier:* a conformant-marked run whose WAS is missing a SHOULD member; a computed SHOULD that omits a process-governing baseline domain. *Bypass closed:* declare a composition and dispatch a different (thinner) one; drop a baseline domain to shrink the SHOULD so a thin WAS trivially satisfies it.
- **REQ-10 — The oracle is unforgeable by the checked agent.** All conformance/efficiency evidence is drawn from harness-produced records (Claude Code transcripts, which the agent cannot author) verified by CI over server-synced state (§264/#815 tamper-evidence keystone) — never from agent-authored claims. *Grade:* independent-oracle (the only tamper-proof grade). *Falsifier:* a control resting on an agent-writable record. *Bypass closed:* the agent fabricates its own conformance evidence.
- **REQ-11 — Cost re-scoped to static price + records-based insight.** Retain the static price (Slice 2: the priced bill at build + CI bloat-gate) and answer the cost questions from the run records (per REQ-14). Retire the telemetry apparatus (OTel collector, dashboards, dollar ledger, calibration-tied-to-dollar-actuals) — under subscription auth, dollars are a projection; the binding constraints are usage windows and operator time (§144). *Grade:* spec-amendment (SO). *Falsifier:* a cost figure without capture-source provenance (§151, retained); a composition whose static price cannot be produced.
- **REQ-12 — Personas and supplements are controls, not prose.** Their enforceable content becomes conformance checks; their required content is delivered by injection (REQ-2/3/4); only irreducible judgment-shaped guidance remains as prose, and it is injected (not description-matched) and audited by the cold review that receives the same slice — the one instrument that catches read-but-ignored (§133). *Grade:* mixed (checks CI-backed; injection by-construction). *Falsifier:* a persona/supplement relied on solely as prose-to-be-read. *Bypass closed:* ship a discipline as a persona sentence and assume compliance (the founding failure).
- **REQ-13 — Review is independent-of-frame always; cold-vs-warm on artifacts is a right-sized dial.** Adversarial review is by a different agent, never given the author's reasoning (independence). Reviewers may be **warm on raw artifacts** (handed the raw diff/design/contract slice) but never on a curated summary (curation re-imports the author's blind spot). True cold (re-load raw yourself) is reserved for terminal rounds guarding collective anchoring. *Grade:* discipline mechanized as a dispatch-composition rule. *Falsifier:* a reviewer handed the author's rationale, or a curated summary in place of the raw artifact. *Bypass closed:* "cold" used to justify redundant re-load without adding independence (the cross-agent waste of REQ-6).
- **REQ-14 — Efficiency insight engine.** A reader over the run records surfaces the AI-Engineer dimensions with provenance on every figure (recorded / measured / judgment): capture-source provenance; cost-band cataloging per operation; prompt-cache discipline (5m vs 1h TTL utilization); sub-agent scope-down (warm vs cold); model-tier + effort right-sizing per task; cross-agent redundant-load. *Grade:* detection/advisory, surfaced through crosslink's existing viewers (§149 "vsdd builds no viewer"). *Falsifier:* an advisory figure without capture-source provenance; a calibration claim with no linked actual.
- **REQ-15 — The design process is itself conformance-checked and Red-Teamed** (operator ruling 2026-07-31). A design/review cycle's own dispatches (including reviews) are subject to REQ-1..10 and REQ-16, and Red Team reviews both the process (was the correct path the only path, or was an easier bypass available and taken) and the artifact (are the controls circumventable). *Grade:* CI-backed (the cycle's own dispatch records are checked) + adversarial review. *Falsifier:* a cycle that declares a composition but whose dispatch records show the personas unloaded (this cycle's own opening — the paraphrase bypass, caught by the operator; and the authoring's Read-not-invoke of the domains — both are findings that the control must be mechanized, not human-caught).
- **REQ-16 — Skill invocation is the audited activation signal** (operator ruling 2026-07-31). The composition's required governing context is delivered and audited as **skill invocations** (`/design`, `/vsdd-phase-<n>`, the composed `/vsdd-domain-*`, the language supplement) — the record of *which skills the agent invoked* is the unambiguous activation signal, checked against the composition's required set. *Grade:* CI-backed audit of recorded skill invocations. Ranking of activation strength: **skill invocation (audited activation) > recorded Read (weaker: content loaded, may be skimmed) > paraphrase-in-prompt (nonconformance)**. *Falsifier:* a run under a declared composition whose skill-invocation record omits a required skill (even if the file was Read); a dispatch relying on paraphrase. *Bypass closed:* Read-instead-of-invoke (the weaker signal — flagged, not passed); paraphrase (nonconformance). This is the single clearest "is the harness cargo-cult" probe: the invocation record either shows the disciplines fired or it doesn't. **Two fail-loud checkpoints (operator ruling 2026-07-31):** (a) *preflight* — a dispatch whose composition is not injected terminates before it runs (REQ-2/3/4); (b) *post-dispatch* — the skill-invocation record is audited after the run against the composition's required set, and **fails loud** if a required primer/domain/supplement skill was not *invoked* (injection-present ≠ invoked-and-used; this closes the injected-but-ignored hole). *Grade:* preventive-terminate + post-dispatch fail-loud CI audit. (Skills are named an under-invoked mechanism in the REQ-20 underutilization audit.)

- **REQ-17 — Phase agent-work is dispatched + audited, never done in the orchestrator session** (operator ruling 2026-07-31; keystone; supersedes the "design is attended, execution is autonomous" split of the 2026-07-20 ruling). The operator/orchestrator session is not a dispatched agent, so nothing it does is conformance-audited — making in-session phase-work the ultimate bypass (the orchestrator does the most work, unchecked). Therefore the **agent-work of every phase — design authoring AND implementation — runs as a dispatched, conformance-audited agent** (subject to REQ-1..16), exactly like reviews. The operator session's only legitimate work is the human's irreducible slots (§161: oracle authorship, triage, ratification, consent grant, spec-intent) plus orchestration (dispatch + audit); its own control is REQ-19. Re-scoped split: **human-judgment attended; all phase agent-work dispatched + audited.** *Grade:* CI-backed (a phase artifact whose authoring/implementation has no conformance-audited dispatch record is flagged) + the same preflight/post-dispatch fail-loud checkpoints. *Falsifier:* a phase artifact (design doc, code) produced with no dispatched, conformance-audited agent record behind it — i.e., done in-session. *Bypass closed:* the orchestrator quietly does the phase-work itself (the whole of this session, and the authoring of this very doc — the live evidence). *Bootstrap interim (marked):* until this subsystem, the crosslink injection point, and a working kickoff (#837) land, phase agent-work is done in-session and **hand-audited** (personas hand-loaded, invocations noted) — a format-carried interim explicitly recorded as such at each dispatch, never the target; this doc's own authoring is a marked instance.

- **REQ-18 — Adopter-inheritance: process-governing baseline ∪ axis-activated product domains** (operator ruling 2026-07-31, contract re-scope in Part 3). The domain roster partitions into **process-governing** domains — inherited by *every* vsdd adopter to FUNCTION — and **product-reviewing** domains — activated per the adopter's product axes. The process-governing baseline is **Solution Owner, Solution Architect, Software Engineer, Quality Engineer** (the always-on baseline) plus **AI Engineer, Platform Engineer, Red Team, Security, Data Engineer, Documentation Reviewer, Technical Writer**, because the process **dispatches AI** (AIE), **enforces via CI/hooks** (PE), **is circumventable + oracle-trust-dependent** (RT + Security), **runs on mdatron schema-data** (DE — the registry + the exercise-registry), and **produces governed prose** (DR + TW), on the SO/SA/SE/QE baseline. Product-reviewing domains — **UX, Accessibility, Privacy, Localization** (plus product activation of RT / DR / AIE) — activate per the adopter's declared axes. The composition SHOULD = **process-governing-baseline ∪ axis-activated-product-domains**, which the verifier (REQ-9) then audits as `WAS ⊇ SHOULD`. *Mechanism:* composition function computes the partition; REQ-9's gate enforces it. *Grade:* CI-backed block (via REQ-9). *Falsifier:* a computed SHOULD (for any adopter/phase) that omits a process-governing baseline domain; a WAS marked conformant while missing a baseline domain. *Bypass closed:* an adopter (or this project) silently drops a process-governing domain (e.g. runs without Red Team or Security), yielding a thinner SHOULD that a thin dispatch then trivially passes — the baseline is inherited to function, not opt-in.

- **REQ-19 — Operator-session control (not a dispatched agent, still audited)** (operator ruling 2026-07-31). The operator/orchestrator session is not a dispatched agent, so nothing it does passes through per-agent conformance audit — the REQ-17 concern at the session level (the session that does the orchestration is otherwise the one unchecked actor). Its control is the **session-start hook** — which injects the session skill + the runtime-determined always-on supplements (`claude-code-cli`, `bash`) + the phase pointer — plus the **read-gate** on governed acts. Per REQ-17 (phases-dispatched) the operator session loads **less**: orchestration + the human's irreducible §161 slots (oracle authorship, triage, ratification, consent, spec-intent); heavy phase context goes to the dispatched agents. It is **not exempt** from the exercise-audit: **session-start-hook-fired** + **session-skill-invoked** are audited and **fail loud**. *Mechanism:* session-start hook (by-construction injection) + read-gate; exercise-audit over the hook/skill trace. *Grade:* by-construction (hook fires) + CI-backed fail-loud audit. *Falsifier:* an operator session with no session-start-hook trace, or with the session skill never invoked. *Bypass closed:* run the operator session bare (no hook, no session skill) so the highest-work, otherwise-unaudited session escapes conformance entirely.

- **REQ-20 — Mechanism-per-control + underutilization audit** (operator ruling 2026-07-31). Every control/surface **names its correct agent-first mechanism** — MCP tool · hook · skill · crosslink affordance · CI leg · sentinel — and rides it; hand-rolling a feature that already exists is **both** §130 nonconformance **and** underutilization (an authored/available affordance left on the table). The **underutilization audit is a first-class design output** of this subsystem, naming for each authored/available mechanism its build/use status and its correct home: the **MCP docs-server** (`vsdd mcp-serve` — PLANNED; add `mdatron.docs.search`; the correct mechanism for crosslink/mdatron knowledge, **not** grepping files; unbuilt = underutilization); **Cron / PushNotification / RemoteTrigger** (scheduled sweeps + budget / rate-limit alerts — unused); **Skills** (under-invoked — Read-instead-of-invoke, REQ-16); crosslink **SWARM** (bypassed for the `Workflow` tool — the leverage-vs-build point); **SENTINEL** (the §149 home for scheduled efficiency-advisory sweeps — unused); crosslink **VIEWERS / mission-control** (§149 "vsdd builds no viewer" — the surfacing home for the efficiency insights); crosslink **INTERVENE** (mid-flow records). *Mechanism:* act-to-affordance map (§130) mechanized as detection + the underutilization audit as a design output. *Grade:* CI-backed detection (hand-rolled-existing-feature flagged) + advisory (unbuilt/unused correct mechanism named). *Falsifier:* a control that hand-rolls a mapped/available affordance with no stated reason; a named correct mechanism left unbuilt/unused where it is the right home. *Bypass closed:* reach for shell/grep/hand-roll to skip an affordance and its checks (the REQ-5 bypass generalized to every mechanism); leave the correct mechanism unbuilt and quietly substitute a weaker manual path — the correct mechanism must be the path of least resistance (RT: correct path = only path).

## Architecture

**Leverage crosslink; supply only the vsdd layer** (§355: crosslink's dispatch primitive "is strong on crosslink protocol and carries none of the vsdd layer"). 
- **Leverage (do not rebuild):** `swarm`/`kickoff` dispatch, worktrees, sessions (phase pointer in breadcrumbs §37), trust/signing, preflight (§108), the viewers — mission control / tui / web dashboard (§149, "vsdd builds no viewer"; the efficiency insights surface there), the MCP docs-server surface (`vsdd mcp-serve`, PLANNED), sentinel (the scheduled-sweep home, §149), and intervene (mid-flow records). The Claude Code transcript is the conformance oracle regardless of orchestrator. Mechanisms currently left on the table are named in the REQ-20 underutilization audit.
- **Build/supply (the vsdd layer crosslink deliberately doesn't carry):** the **composition function** (Slice 2 — the SHOULD, computed as process-governing-baseline ∪ axis-activated product domains per REQ-18, plus the runtime/project always-on supplements per REQ-4); the **injection point** into the dispatch prompt — **vsdd-owned** (vsdd assembles the prompt from the composition and rides crosslink's dispatch primitive, §355) until crosslink absorbs it via a generic injection hook in kickoff prompt-assembly (the §81 injection seam, filed as a crosslink feature request); the **conformance verifier** as a **Slice-4 gate leg** (`vsdd gate conformance`) that reads the transcript WAS, compares to the SHOULD, and gates; the **efficiency insight engine** as a **sibling command** (reader over records, provenance-tagged). Verifier + engine home in `vsdd-core` (pure over the records) with a `vsdd`-binary command surface; they consume the same run records analyzed by hand this session (`agent-<id>.jsonl` usage/tool events; the journal). The static-price half of Cost stays in Slice 2 (REQ-11).
- **The oracle + trust boundary (SA/RT):** the checked agent is untrusted with respect to its own conformance; evidence comes from the harness-produced transcript + CI over server-synced state (§264/#815). This is the hard-to-undo trust-boundary placement — the verifier must never read an agent-writable record as authoritative.
- **Delivery of injection while the upstream capability is unbuilt:** during bootstrap, injection is format-carried (the dispatch prompt assembles the required primer/domains/supplements from the composition) with the recorded Reads as the interim verification, until crosslink's kickoff prompt-assembly ships the §81 injection seam (#837); the skill-invocation audit (REQ-16) becomes the activation signal once it lands.

## Design decisions (resolved)
